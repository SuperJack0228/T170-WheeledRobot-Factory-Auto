# 料盘放置：邻孔定位、遮挡处理与平滑撤离

更新于 2026-10-29。基于现场版本 `99d9732`，与本次合爪后收手修正共用控制与轨迹交接。以下描述对应实际新增源码；不依赖旧版手相机放置说明。

## 这一版解决什么

头相机仍负责选择空孔和给出粗位置。手相机不再寻找“离十字线最近的空孔框”，而是固定头相机选中的 **ArUco 行号、列号**，利用可见邻孔或盘面标记推算该孔的图像投影。工件完全挡住目标孔时，目标身份也不改变。

这一版假设工件相对夹爪的位置基本固定。它不估计工件在夹爪中的偏心、滑动和歪斜，也没有接触力控。

## 实际执行链路

1. **头相机选孔**：沿用当前 ArUco 料盘解算和 YOLO 空孔分类，保存本张图各孔的原始三维盘面坐标，以及选中的行、列。原有整盘偏置暂时作为粗定位前馈保留。
2. **建立粗几何**：读取与头相机同一份 `board_yf100_aruco/config.yaml`，从已知孔网格和头相机解算出的孔心拟合料盘坐标系。腰前伸时，盘面锚点和动作目标一起补偿；启动前再转换到实际手臂基座坐标系。
3. **接近并固定姿态**：复用当前接近与下降衔接。手相机只在下降、姿态成立后提交观测。
4. **RGB 几何观测**：手相机取 RGB，按实际图像时间戳查询插值后的实测机械臂状态。既不读取深度图，也不为放置调用手部 YOLO。
5. **定位指定孔心**：先去镜头畸变。可见标记提供角点约束；邻孔 ROI 根据当前透视关系校正到盘面，拟合孔口圆周，再恢复真实孔心的图像投影。
6. **连续修正 XY**：将指定目标孔的“虚拟孔心”作为带时间戳的观测，复用现有高度相关映射、延迟补偿、PD、预测制动和下降速度协调。目标孔不需要重新出现在图像里。
7. **末段提交**：达到当前放置对准条件后，沿用控制器的冻结目标和末段下降，不要求被遮挡的目标孔再次可见。放置使用精定位容差，不套用抓取的宽松结束条件。
8. **张爪与撤离**：下降完成后继续发送最终保位位置；预规划收手与张爪重叠。被选中的两手可以同时张爪，确认反馈后，交接给平滑上抬、收手轨迹。

“虚拟孔心”是根据可见结构推算的目标投影，不是拿最近邻孔冒充目标，也不是直接复用上一帧像素。相机移动时会根据实测位姿重新投影。

## 透视和遮挡怎么处理

原图中，圆孔投影的椭圆中心不一定是真实圆心的投影，检测框中心更不能保证是孔心。这个几何问题也有专门的研究：[Center of circle after perspective transformation](https://arxiv.org/abs/1902.04541)。本实现采用盘面透视校正后再提取孔心的路线，没有复现该论文的同心圆算法。

平面映射采用 [OpenCV 的单应性模型](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)。RANSAC 用来筛选一致的对应点；物理位姿再用带先验的 [`solvePnP`](https://docs.opencv.org/4.12.0/d5/d1f/calib3d_solvePnP.html) 刚体优化，而不是直接接受噪声单应矩阵的全部自由度。

具体退化策略：

- 有可用标记角点：根据头相机粗几何分辨标记所在角位。当前料盘使用重复 ID，因此不能直接把 ID 当作角位。标记会先修正粗几何，再搜索周期性孔网格，避免邻孔以错误的整孔间距匹配压过标记。
- 有至少四个不共线邻孔：尝试完整盘面几何更新，剔除不一致点，再检查重投影、位姿变化和目标身份范围。
- 只有两个或三个可靠邻孔：保留盘面姿态和透视先验，只估计一致的平移，不从两个点强行计算八自由度单应矩阵。
- 局部被遮住的邻孔：圆周覆盖不足、圆径不符或拟合残差过大时弃用。目标孔本身始终不参与邻孔拟合。
- 可见结构不足：不提交新的观测，不制造“新时间戳的旧像素”。尚未完成精对齐时，由原控制器减速、等待或超时报错；已经满足条件并进入 commit 时，按原末段逻辑完成下降。

只靠周期性孔阵列无法凭空判断自己偏了整整一格。因此无标记时，仍需要头相机和粗手眼关系把关联限制在正确格子附近。当前邻孔关联半径 25 mm，小于 75 mm 孔距的一半；标记间距更大，允许更大的初始平移修正。此实现会修正当前任务中的料盘估计，不会自动覆盖永久手眼标定文件。

## Z 的含义

机械臂最终下降高度 C 仍由原有料盘放置配置确定。没有用相机深度改写 C，也没有增加自主向下探测动作。

日志里的 `observed_plane_z_m` 是视觉几何估计的盘面高度，用于计算像素映射中的成像距离和随高度变化的参考点。它与“修改机械臂下降终点 Z”是两件事。下降速度仍会随 XY 剩余误差和可用修正时间协调。

## 配置和首次现场确认

定位参数在 `visual_servo.tray_place`：

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| `enabled` | true | 使用新邻孔/标记定位 |
| `board_config` | board_yf100_aruco/config.yaml | 与头相机一致的料盘物理尺寸和码参数 |
| `association_gate_m` | 0.025 | 邻孔关联范围，必须小于 0.45 倍孔距 |
| `reprojection_gate_px` | 3.0 | 几何一致性检查 |
| `circle_residual_m` | 0.0015 | 校正到盘面后的圆周拟合容差 |
| `max_plane_update_m` | 0.030 | 普通单帧盘面估计更新范围 |
| `min_neighbors` | 2 | 无标记时的最少可靠邻孔数 |
| `rectified_pixels_per_m` | 2000 | 局部盘面校正分辨率 |

放置参考像素仍使用独立的 `visual_servo.left_place`、`right_place` 配置：

- `reference_px` 应代表工件轴心在正确放置高度的图像投影。
- `reference_height_m: 0.0` 表示参考像素在最终 C 高度取得；若在更高处示教，需要填写相对 C 的高度。
- 当前未另填 `reference_px`，加载器会沿用该手现有参考像素。这是初始值，**不能把抓取现场成功等同于放置参考也已验证**。
- 首次应通过独立的现场观察确认工件轴心与目标孔对齐，再记录对应的虚拟孔心作为参考。不能把算法自身认为“两点重合”当成独立标定证据。

在“同一夹爪、同一装夹方式、工件相对夹爪基本固定”的前提下，这是一组每手的工具参考，不需要为 36 个孔逐一填写像素偏置。若后续夹持偏心或工具更换，需要重新评估该前提。

撤离和张爪参数在 `tray2_place`，与抓取后的撤离独立：

```yaml
retract_lift_m: 0.08
retract_lift_vel_m_s: 0.40
retract_return_vel_m_s: 0.40
pre_open_settle_sec: 0.0
open_tolerance_rad: 0.2
open_timeout_ms: 1500
```

0.40 m/s 是规划速度，8 cm 是目标抬升量，仍受原有工作高度范围约束。没有额外插入停留；转弯无法生成合适的短平滑连接时，保留 SDK 加减速轨迹，局部可能减速。

## 张爪失败如何处理

旧逻辑在 `openAndWait()` 返回 false 时只打印警告，后面仍可能计作放置成功。新逻辑要求该手已配对、有反馈、通信正常、无电机错误且张开位置得到确认。SDK 将“没有配对夹爪”视作成功的行为不会用于确认放置。

- 一手确认张开、另一手失败：只记录已确认侧，保留未确认侧的持件闩锁，报告 `ReleaseFail=6`，执行入口返回 `-38`。
- 不自动重新放置，也不在张爪未确认时直接收手，避免把尚未松开的工件从孔中拉走。
- 收手预规划会回收并丢弃，保位由后续明确动作接管。
- 张爪确认后的收手若失败，沿用 `MotionFail=5` / `-37`，已确认放置结果保留。

夹爪编码器确认张开不等于独立传感器已经确认工件落入孔中；目前没有新增工件落位检测。

## 编译与命令

机器人端使用现有环境重新编译：

```bash
cmake -S . -B build_robot
cmake --build build_robot -j4
./build_robot/t170c_debug 2>&1 | tee startup.log
```

C++ OpenCV 需要提供 ArUco、calib3d 和 imgproc。代码兼容 OpenCV 4.7 前后的 ArUco 字典 API 差异。

现有命令行为保留：

| 命令 | 行为 |
| --- | --- |
| `tray2` / `tray2_place` / `tray2_precision` / `tray2test` | 仍走原精度测试：不松爪，按原测试逻辑暂停和继续 |
| `tray2_auto` | 新增正常放置入口：根据当前持件判断选择手臂，到料盘二，对准后真正张爪，撤离，停在料盘二，不自动返回料盘一 |

调度中的正常料盘二放置调用也已接入新链路。`tray2_auto` 的持件判断沿用现有夹爪反馈/闩锁，不是新增的物体存在传感器。

先用保留的精度测试确认两手参考点及孔位身份，再使用正常放置入口验证张爪和快速撤离。注意，精度测试不会执行完整的真实松爪撤离流程。

## 日志与反馈

沿用 `logs/visual_servo/servo_*.csv`，新增：

- `vision_source`：`neighbor_homography`、`neighbor_translation`、`marker_homography`。有标记和邻孔混合约束时也归入 marker 来源。
- `virtual_target`、`target_row`、`target_col`：确认整段跟踪是否一直指向头相机选中的同一孔。
- `neighbor_count`：通过圆周筛选的邻孔候选数；最终模型可能只采用其中的 RANSAC 内点。
- `marker_corner_count`、`plane_reprojection_px`：可见标记角点和内点模型的一致性；重投影误差不是独立的物理放置误差。
- `observed_plane_z_m`：成像几何中的盘面高度。
- `infer_ms`：放置时记录几何处理及等待捕获状态的耗时，不再表示 YOLO 推理。
- `gripper_start/open`、`gripper_end/open_confirmed` 或 `open_failed`，以及上次收手补丁的 `retract_*` 事件。

每次 session 还会保存参数、实际目标行列与初始盘面矩阵 `.tray_target.yaml`，以及磁盘上的料盘参数副本 `.tray_board_on_disk.yaml`。后者标明 on-disk，避免将后续磁盘文件变化误当成当时内存值。

```bash
python3 tools/analyze_visual_servo.py logs/visual_servo --json servo_summary.json
```

汇总包含定位来源、目标孔编号、邻孔数量、几何处理耗时、张爪确认和撤离信息。首次验证反馈请保留完整 startup 日志、当次 CSV 和参数快照；若定位不足，手相机原始 RGB 比只有最终误差数字更有诊断价值。

## 模块边界和本地验证

- `tray_localizer.h/.cpp`：独立 RGB 几何定位；输入图像、相机实测位姿和指定孔身份，输出虚拟孔心与质量信息，不发电机指令。
- `hand_shadow.cpp`：取帧、捕获状态关联、按手和 session 管理定位器、提交观测。
- `servo/runtime.cpp`：实测状态历史、像素映射、控制器、保位交接和日志。
- `move_box_runtime.cpp` / `grasp_to_standby.cpp`：目标绑定、张爪、预规划与流程结果。

本地测试覆盖：完全遮住目标孔、两个邻孔退化、局部遮挡孔周、丢失全部特征、透视和畸变、粗姿态误差、重复码与整盘 180° 旋转、标记单独定位、移动相机及左手旋转图像约定；另有双手合成动力学的虚拟孔心下降与较严格的放置张爪门限测试。原抓取、配置和收手交接回归继续执行。

这些是合成图像和模拟接口测试，不能证明真实反光金属、真实孔口边缘、光照及机器人 SDK 上的效果。Mac 没有完整机器人 Linux SDK，完整编译和双手现场验证仍需在机器人端完成。
