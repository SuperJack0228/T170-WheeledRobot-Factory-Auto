# 双臂 Home、肘部策略与有效限位

更新：2026-11-19，针对 11 月 18 日现场反馈。适用于当前 `Ti5_Robotics 20261109` 接入层；交付 SDK 二进制未更换。

## 1. Home 的执行行为

`home → go_home → move_arms_to_home → arm_joint_home`。

两臂先检查当前角到各自固定 Home 的关节路径，再并行执行。执行期间保持夹爪状态，使用同一套速度、加速度、jerk 与编码器到位反馈。双臂返回成功后，原有头/腰准备流程继续执行；一侧失败不继续后续腰部阶段。

Home 不再调用 TCP 逆解，不经过旧的抬升、XY 平移、校正 Z、原地转腕等笛卡尔阶段。改变起点不会改变目标关节构型。旧 `home_tcp` 字段保留兼容读取，不再决定 Home 指令的关节目标。

模型默认 Home 对应名义 260 mm 工具下的 TCP `(0.45, ±0.35, -0.10)` m、RPY 约为 0；肘部位于肩部下方，并在左右本侧展开。3 kg 保留原始模型的小量非理想轴差异，关节值不要求机械地逐项完全镜像。

固定关节返回仍受运动能力和有效限位约束，不能理解为任意姿态瞬间返回。当前不包含全身/环境碰撞规划；关节轨迹本身不能证明夹持工件已脱离孔位或机床。

## 2. 外置配置

| 配置 | 文件 |
|---|---|
| 3 kg Home 与肘部偏好 | `config/robot_models/t170c_v2_3kg/motion_policy.yaml` |
| 5 kg Home 与肘部偏好 | `config/robot_models/t170c_v2_5kg/motion_policy.yaml` |
| 当前机器人型号选择 | deployment 中的 `robot_model` |
| 运行时实际载入的策略 | 生成目录 `config/arm_binding.yaml` 的 `motion_policy` |
| 关节回程速度、加速度、jerk、到位等待 | `config/defaults/factory_baseline.yaml` 的 `retract_motion` |

策略配置中的角度为 **SDK 模型角、度**，不是直接下发给电机的设备角。设备方向和零偏仍只在正常 IO 边界转换一次。

| 字段 | 含义 |
|---|---|
| `left/right.home_deg` | 固定 Home 的七轴目标 |
| `left/right.preferred_deg` | 求解时的偏好构型，作为软目标而非锁关节 |
| `posture_gain` | 向偏好关节姿态靠拢的强度 |
| `elbow_gain` | 向几何肘部目标靠拢的强度 |
| `limit_gain` | 接近关节边界时的回避强度 |
| `elbow_outward_ratio` | 相对重力向下方向，增加多少本侧向外偏好 |

这些策略在启动时载入，修改后通过部署脚本重新生成 runtime 并重启。3/5 kg 随机型选择自动切换，不需要更换 `.so`。旧运行目录缺少新策略时会拒绝作为新程序的生产配置，不能直接复用。

## 3. 局部求解与肘部目标

共用求解核心为 `src/motion/bounded_ik.cpp`。普通直线、手相机局部修正、标定微调和竖直撤离使用相同的边界 QP 核心，各场景采用不同的迭代预算和连续性范围。

每次迭代求解一个七变量凸二次规划，将关节增量上下界直接放入问题。到达某轴边界时，其余轴可以重新分配运动，避免原实现只缩小一整组增量。

TCP 位姿是主任务。次级方向包括偏好关节姿态、肘部几何目标和近限位回避，并投影到任务零空间。局部迭代后进行主任务残差收敛检查；次级目标不能代替末端位姿验收。

几何肘部目标依据肩点、目标腕点、上臂和前臂长度构成的肘部圆计算。偏好方向为任务基座向下加本侧向外分量，当前直立工况下近似重力方向，随目标位置和姿态变化；左右使用同一镜像规则。不强制所有动作采用同一个 J2，也不强迫不同任务目标下的两臂关节数值相同。显式配置的其他示教关节目标保持其给定构型，不会在执行中重新选解。

通用单点逆解使用当前角、偏好构型及其扰动作为候选起点，再比较肘部偏差、偏好构型距离和起点距离。取消无法提供连续性保证的固定初值供应方数值回退。连续轨迹不做全局换解，沿用上一点，并限制相邻关节变化。

这些是软偏好和局部优化，不是对所有工作空间的自然姿态、全局可解性或碰撞安全证明。空间不足、任务约束冲突时仍可能返回明确失败。

主要肘部构型在接近规划阶段建立。在线伺服的次级关节步长同时受本轮 TCP 增量与单周期加速度预算限制，避免将一个固定大小的零空间动作叠加到很小的 XY 修正上。竖直撤离的采样轨迹仍由统一时间参数化约束。

公开方法参考：

- [Pink 的任务与约束 QP](https://github.com/pink-kinematics/pink/blob/main/pink/solve_ik.py)、[PostureTask](https://github.com/pink-kinematics/pink/blob/main/pink/tasks/posture_task.py)：参考任务、偏好姿态与边界约束的建模方式。
- [TRAC-IK 官方集成说明](https://github.com/moveit/moveit2_tutorials/blob/main/doc/how_to_guides/trac_ik/trac_ik_tutorial.rst)：参考关节限位处理及种子距离选解原则。

当前代码为应用层 C++ 实现，没有引入这些项目的运行依赖，也未迁移 ROS 2。

## 4. 有效限位与下发

启动后读取两臂各轴的驱动位置下限、上限，单位为设备输出轴 rad；不写入驱动限位。根据该机的方向与零偏映射到模型角后，与所选 URDF 模型范围取交集。J2 换算后靠近 0 的那一侧再放开 2°：本机驱动约 ±85° 对应的模型角从 ±5° 变为 ±3°，仍不超过模型范围。

求解、撤离、标定、轨迹采样检查和正常关节下发共用这一有效范围。范围数据通过统一状态和互斥保护读取，避免两个模块持有不同的设备限制。驱动范围无效、无法读取、交集为空或 Home 不在范围内时，启动给出具体错误。

旧 `enforce_sdk_joint_limits` 字段暂留兼容；读入 false 也归一化为 true，不再允许伺服单独绕过限制。

直线轨迹的 IK 控制点使用凸包保持的 C2 夹持 B 样条近似，避免普通样条在限位附近越过控制点范围。时间参数化检查完整采样流的速度、加速度与 jerk；随后再检查实际 FK 的直线、姿态偏差和关节界限。该路径不会在每个 IK 点停住。

## 5. 失败与日志

轨迹发送完不等于实际到位。到位超时向上返回 `-8`；硬件中止、CAN 故障保持原有分类。笛卡尔阶段失败后不继续执行其后续阶段；到位失败时优先保持当前测得的位置。

| 日志 | 用途 |
|---|---|
| 启动 `[arm_limits]` | 两臂设备范围、有效模型范围及快照位置 |
| 当前 runtime 的 `logs/arm_limits.yaml` | 机器人编号、机型、CAN ID、设备/有效范围、Home 目标 |
| `[home_joint]` | 两臂固定目标、预规划时长、实际返回码 |
| `[retract] stage=home_joint` | Home 命令、实际反馈、跟随误差、到位/超时事件 |
| `[arm_plan]` | 每段直线的规划耗时、轨迹行数、名义运动时长 |
| `[arm_ik]` | 失败路径点、起始模型角、目标位置、残差、接近的边界轴 |
| `logs/visual_servo/servo_*.csv` | `home_joint_start/feedback/command_complete/measured_arrival/arrival_timeout` 等事件及双臂关节命令/反馈 |

Home 即使发生在第一次视觉伺服之前，也会启动异步 CSV 记录。存图与逐帧同步写盘没有加入运动循环。

## 6. 机器人更新与最小验证

在机器人仓库根目录重新编译，并使用维护入口启动，以生成带新策略的运行目录：

```bash
cmake --build build_robot --parallel 2
unset T170_ROOT T170_CONFIG_DIR T170_RUNTIME_DIR T170_DEPLOYMENT
./deploy/run_maintenance.sh 2>&1 | tee home-motion-test.log
```

停止旧主程序后再启动上述入口。先从已脱离料盘、周围有空间的姿态验证一次 Home，再执行准备姿态并返回 Home，比较两次最终关节角。随后验证固定姿态平移、短距离下降修正和抓取撤离。

反馈数据保留终端日志、当前会话 `arm_limits.yaml` 和 `servo_*.csv`，不再仅保留界面返回的一个错误码。3/5 kg 的 Home 均已做模型 FK 检查；真实构型、扫掠空间、驱动限位查询及 Linux SDK 耗时仍需实机确认。

本地验证结果与名义轨迹耗时见 [2026-11-19 验证记录](../validation/arm_motion_policy_20261119/RESULTS.md)。
