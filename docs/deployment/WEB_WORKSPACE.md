# 调试台与机器人档案

更新：2026-11-19。适用于 Web API 8 / UI 2.1.0。

当前恢复原有顶部导航、三列紧凑动作卡片及分组配色。料盘准备的近/中/远排通过选择框切换；机器人档案与维护/生产模式功能保留。禁用的相机预览不再占用页面空间。

## 启动与更新

停止旧主服务后，在仓库根目录执行：

```bash
cmake --build build_robot --parallel 2
unset T170_ROOT T170_CONFIG_DIR T170_RUNTIME_DIR T170_DEPLOYMENT
./deploy/run_maintenance.sh 2>&1 | tee startup.log
```

另开一个终端，在同一仓库中启动网页：

```bash
./deploy/run_web.sh
```

使用终端打印的网页地址与 token。网页启动脚本自动连接当前主服务的 runtime，无需手工填写 `session.*` 路径。本次网页后端和静态资源都有更新，应重启旧网页进程并刷新页面。

生产运行改用 `./deploy/run_factory.sh`。网页不能热切换主服务的维护/生产模式，也不会自行终止另一个终端启动的主服务。

## 页面与动作

| 页面 | 功能 |
|---|---|
| 状态 | 服务、底盘、持件、腰部与双臂 TCP；顶部显示当前运行编号与机型 |
| 动作 | 姿态准备、料盘抓放、传送带抓放、识别诊断；其他维护动作折叠显示 |
| 任务联调 / 生产调度 | 维护模式显示手动技能编排；生产模式显示调度监控与进入/退出调度 |
| 标定向导 | 维护模式下完成料盘抓取、放置的左右手独立标定 |
| 参数 | 查看运行参数；分层生成的快照只读，按来源 YAML 修改并重新生成 |
| 机器人档案 | 选择或创建机器人编号、选择 3/5 kg，保存下次启动档案 |
| 视觉 | 手相机预览及头相机最近检测结果；预览仍按原配置开关启用 |
| 日志 | 网页动作结果与当前网页进程收集的终端日志 |

动作元数据由 `web_debug/actions.py` 维护，执行入口仍为 C++ `src/app/command_catalog.cpp`。页面通过 `/api/actions` 与当前主服务的能力目录交叉过滤：未知命令和退役命令不生成按钮，生产模式不开放手动动作。旧整圈实验、旧伺服测试和重复别名不再显示；并未删除仍在使用的底层技能。

`vision_grasp_once`、`tray2_auto`、`belt_grasp` / `belt2_grasp`、`belt` / `belt2` 分别保留为常用抓放入口。界面重新分组不改变原有工位流程和调度协议。

网页“手动上料”编排调用 `vision_grasp_once → belt`，抓取后保持夹持；不会使用每轮松爪的清盘测试入口。无目标、部分完成、动作失败分别显示，失败时停止编排。动作结果常驻页面提示栏，原始返回与失败阶段在“查看返回详情”中保留。运行期间不重复开放普通动作按钮，停止按钮继续可用。

## 机器人档案切换

1. 打开“机器人档案”，核对“正在运行”和“下次启动”两栏。
2. 在下拉框选择已有机器人编号，并选择实际机械臂型号。No.124 仍绑定 3 kg。
3. 点击“保存为下次启动档案”。后端使用正式部署解析器完整校验配置，再原子写入选中 deployment 与 `config/deployment.yaml`。失败时不切换选择入口。
4. 停止主服务，清除旧的显式 runtime/deployment 环境变量，再通过维护或生产脚本启动。顶部“当前运行”应更新到新的编号和机型。

保存不会改变正在运行的关节模型、工具变换或电机绑定。型号即使在同一份档案中修改，也会显示等待重启。生产模式和标定会话期间不允许写入档案；主服务离线而网页仍在运行时，可设置下次启动档案。

### 新增机器人

展开“新增机器人档案”，填写完整编号（例如 `TH-T170C-0125`）、底盘地址，并在上方选择模板及 3/5 kg。创建会生成：

```text
config/deployments/TH-T170C-0125.yaml
config/robots/TH-T170C-0125/
config/calibration/TH-T170C-0125/tasks/
```

模板中的电机绑定、工具、相机配置与示教初值会复制到新编号；`identity.yaml` 的编号和底盘地址同步更新。相机 SN、工具安装及示教初值仍须对应新机实际情况。

新机器人不会继承模板的头/手眼或四份料盘任务标定。页面会列出缺失基础文件的目标路径；按 [快速部署指南](NEW_ROBOT_DEPLOYMENT_GUIDE.md) 导入本机基础标定后，才能保存为启动档案。四份料盘任务标定可在维护向导中生成。创建本身不自动切换当前选择，也不启动硬件。

## 标定图片修复

旧接口将图片相对路径拼接到网页启动时的项目目录。网页与主服务 runtime 不同，或网页保留运行而主服务切换会话时，会从错误目录找图。本次状态响应增加 `runtime_root`，图片接口以当前标定会话返回的目录为准；兼容旧状态时通过主服务 `ping` 查询目录。

图片仍要求会话 ID、版本号一致，且路径必须位于该 runtime 的 `debug_picture/calibration/` 内。头相机重拍使用独立版本文件，避免读取正在覆盖的旧图。前端读取完整图像后再显示，错误直接显示到标定页面，并等待图片解码后才接受参考点点击。

`runtime_context.sh` 同时修复无效显式目录被 `export` 掩盖、随后退回源码目录的问题。错误目录会直接报错退出。

图片显示与机械臂运动是两条链路。此次修复图片路径和交互；标定接近、局部微调仍调用当前有界逆解与播放器，不在网页层绕过运动失败、限位或反馈检查。真实手臂能否完成向导全流程仍以现场结果为准。

## Home 与肘部

3/5 kg `motion_policy.yaml` 均已更新整组七轴 Home 与偏好构型，向外偏好比例为 0.5。名义 260 mm 工具下保持 TCP `(0.45, ±0.35, -0.10)` m、RPY 为 0；不是单独增加 J2 后任由手腕倾斜。

Home 继续使用固定关节轨迹。新参数必须重新生成 runtime 并重启主服务；`reload_config` 不重新加载机械臂模型策略。详情见 [运动策略](ARM_MOTION_POLICY.md)。

本次未替换供应方 SDK 二进制，未修改调度协议，也未改动现场提交中的 J2 内侧限位处理。

## 2026-11-19 第一批恢复修复

- 手眼矩阵由 `src/config/extrinsics.cpp` 通过 YAML 解析器读取，支持 `a. matrix` / `matrix`、4×4 多行/行内数组及 16 项平铺数组。平移从毫米转换为米一次，失败保留调用方原有数据，报错包含文件路径。
- 抓放任务在准备动作前读取所需手眼配置；向导建立会话时检查所选手。既有的闭环启用要求提前验证，不新增精度、速度或质量门限。
- 标准技能结果通过兼容层保留 `native_code`、`failure_stage` 和各手的持件/放置状态。初始化、设备与运动错误直接向上报告；找不到目标、空抓仍沿用现有处理分支。
- 单步命令不再把所有非负返回值视为成功。`code=2` 且完成数为 0 是失败，有完成数量则为部分完成；`code=1` 为无目标。网页同时拦截旧主服务的历史误报响应。
- HTTP 请求结束与动作成功分开处理，后台任务保留错误。原始失败阶段采用实际调用报告的阶段，避免沿用上一条进度阶段。
- 旧日志“手相机已关闭”改为分别说明旧版停点复检与连续下降伺服的开关状态。

此批没有修改逆解、轨迹插值、时间参数化、速度、jerk 或 Home。现场几十秒慢动作及标定微调的到位精度问题仍属后续批次，不能将界面恢复和矩阵兼容修复理解为这些问题已解决。验证与截图见 [第一批恢复验证记录](../validation/phase1_recovery_20261119/README.md)。
