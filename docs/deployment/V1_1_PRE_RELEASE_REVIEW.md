## 已修复的问题

| 项目 | 原行为与影响 | 本次处理 |
|---|---|---|
| 异常待命退出 | 收信等待超时后直接 join，收信仍阻塞时会挡住后续关闭连接，退出调度可能卡住 | 超时保留同一收信线程；仅回收已完成线程。退出仍先关闭连接再等待收信结束 |
| 下料任务误报完成 | 料盘放置以正数 1／2 表示无空孔／未全部放置；调度只检查负数，可能继续发送 DONE | 同时检查返回码、每个原持件手的放置确认及剩余持件状态；未完成则原地待命，不发 DONE。满盘上报保留 |
| 源码配置无法导入 | 升级入口要求旧目录有 release.json，正在使用的源码调试目录不满足 | 识别完整源码结构和 packaging/VERSION，记录 source_kind、提交及修改状态，导入原配置并备份 |
| 旧理论手眼复发 | 导入整个旧 config 可能重新带入错误的 urdf_wrist 声明 | 仅识别原始 CAD 矩阵和旧声明，修正为 legacy_t7_flange。实测／修改后的矩阵不替换，任务指纹不改；校验不通过回滚 |
| 打包版本不统一 | CMake 项目版本与打包版本分别维护，安装清单固定携带 1.0.0 发布说明 | 项目版本、运行包版本和当前发布说明统一读取 packaging/VERSION |
| 依赖检查残留 | install-check 目录重复使用，旧文件可能掩盖本次未安装的依赖 | 每次创建全新的临时检查目录，完成或失败后清理 |
| 历史测试预期过期 | 历史参数对照仍期待传送带伺服关闭、旧修正速度及旧抓取姿态 | 仅显式更新本次现场已提交的四项控制变化，其余参数仍与历史对照检查 |

## 原生构建和调度联调仍需完成

Mac 不能在当前原生构建链路生成机器人使用的 Linux ARM64 程序。需要在匹配环境的 No.120、No.124 或 Linux 构建机执行 packaging/build_release.sh，完成真实链接、ldd 依赖核对并生成 TGZ／SHA256。

调度联调关注三个结果：收得到并执行任务、未成功的动作不会上报完成、退出调度能回到维护状态。生产启动入口仍自动进入调度，应在联调通过后使用。

当前外部 SDK 适配层通过析构 RobotClient 解除 apply_mission 的阻塞，再 join 收信线程。本地没有现场 SDK 的实现，无法确认该析构与正在执行的成员函数是否具备线程安全保证；适配器的互斥锁只保护指针取出／转移，不保护整个 SDK 调用生命周期。现有契约替身能验证应用退出顺序，不能消除此项 SDK 层疑问。本次不猜测并改写该关闭协议，需在现场 SDK 上确认或由 SDK 提供明确的可取消收信／disconnect 接口。
