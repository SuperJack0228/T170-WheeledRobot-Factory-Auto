# V1 候选版冻结记录

候选版本：`1.0.0-rc.1`；本地标签：`v1.0.0-rc.1`。基线提交与配置摘要见 `config_parity.json`。标签对应最终代码提交，不包含远程推送或正式发布操作。

## 变更范围

- 网页现有 98 项常调字段迁入本机 `quick_params.yaml`，原层对应字段移除，保持唯一归属；自动生成的完整输入改名为 `effective_params.yaml`。
- 网页与终端共享持久保存、校验、空闲热更新和下次启动加载流程。工作区文件锁覆盖字段读取、修改和写入，主程序保留硬件锁及配置锁。非法网页修改回滚；忙碌和重启需求明确区分保存与应用；回执丢失或次要运行记录失败不回滚已提交参数。
- 新机器人默认使用头、左右手相机理论值，生成时适配 3/5 kg SDK 法兰与实际左右图像方向。No.124 现有手眼、任务参考、模型与有效动作参数保留。
- 增加可迁移安装目录、持久配置工作区、外置日志、新机建档入口、版本与环境清单，以及 TGZ/SHA256 构建规则。Linux 构建检查安装目录的动态依赖，拒绝缺失或仍依赖源码的运行库。
- 本次不修改抓放算法、动作轨迹或调度任务逻辑；网页布局保持原有组织。

## 后续发布步骤

1. 在与目标机器人兼容的 Linux 环境检出候选标签，保持源码工作区干净，执行 `./packaging/build_release.sh`。
2. 构建脚本完成原生编译、安装依赖检查和 CPack 打包，输出 TGZ、SHA256、版本及环境清单。
3. 在现场验证维护启动、网页持久调参、双手抓放和调度闭环；记录实际任务与故障结果。
4. 候选通过现场验证后发布对应归档；第二台机器人解压同一归档，运行 `setup_robot.sh`，填实际型号、编号和相机 SN，建立本机四份抓放参考后投入任务。
