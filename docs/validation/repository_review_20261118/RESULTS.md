## 优先处理的问题

### 1. P1：动作期间重载共享配置没有统一排他保护

源码证据：

- `src/app/command_router.cpp` 先执行 `handle_runtime_commands()`，随后才获取 `g_hw_mu`。
- `src/app/commands_runtime.cpp` 的 `reload_config` 仅在标定会话激活时拒绝，持 `g_config_mu` 后直接重新赋值 `g_move_cfg`。
- 自动作业入口 `src/app/boot_dispatch.cpp` 持有 `g_hw_mu`，任务文件持续读取 `g_move_cfg`，没有使用重载持有的 `g_config_mu`。

因此自动任务或手动动作尚在执行时，仍可能通过另一请求重载全局对象；读写没有共同同步机制，存在数据竞争及一次任务混用参数的风险。当前伺服会话已复制一部分控制参数，但未覆盖整条任务链。

建议先限制为动作空闲时重载，并统一锁顺序；后续改为任务开始时取得不可变参数快照。SDK、设备绑定和机型选择继续采用重新生成运行目录并重启生效。此问题由源码路径确认，未进行 ThreadSanitizer 或真实调度复现；本轮没有改变重载策略。

后续更新：用户授权后已实现空闲重载排他保护、后台配置短读锁、完整候选校验和启动资源变化检查，详见 [参数操作](../../deployment/PARAMETER_OPERATIONS.md)。观察器算法选择随会话复制，避免后台继续读取可变全局配置。新增 `config_reload_test` 验证忙碌/标定/退出拒绝、无效配置保留、启动绑定要求重启及后台读写串行。上述段落保留发现时的证据，不再表示重载路径仍未处理；完整任务参数快照及全仓其他共享运行状态仍属后续工作。

### 2. P1：局部视觉伺服与后续轨迹的模型限位规则不一致

源码证据：

- 当前 `config/defaults/factory_baseline.yaml` 中 `enforce_sdk_joint_limits: false`。
- `src/motion/kinematics_adapter.cpp::solve_local_pose()` 在该开关关闭时，只限制相对会话起点的关节变化，不使用 `Arm::Check_Joint_Limit()`；这里调用新 SDK 的 FK，自行进行局部数值求解。
- `src/motion/arm.cpp::Joint_Trajectory()`、`Line_Trajectory()` 始终检查所选模型限位，起点超限时返回 `-3`。

这意味着伺服可能接受一个模型限位外、但仍处于局部变化范围内的关节解；之后抬升/收手规划又因该起点超限而拒绝。这里描述的是源码允许出现的交接条件，不是对历史现场故障原因的直接认定。

建议统一任务各阶段的约束来源，并在抵达边界前协调修正；不要仅靠关闭后续检查处理。是否需要校正 URDF 名义限位或使用经过确认的运行限位，应单独核实，不能从过去开环可走推断所有超限都可接受。本轮不擅自改变已调好的伺服门限。

上一轮“新 Arm 逆解和轨迹始终检查模型限位”的说法只适用于其自身接口，不能扩展到所有使用 FK 的独立伺服求解。此次修正预检文字，明确两条路径的区别。

### 3. P2：配置已分层，但尚未全部外置

明确示例：

- `src/tasks/transfer.cpp` 的 `kTransferPlaceZBiasM = -0.005` 会覆盖转运放置配置中的高度偏置，这是场景数值，仍在代码里。
- `src/app/hardware_factory.cpp` 在创建夹爪时直接指定力矩阈值、滤波、slew rate 与检测次数，尚未从实例/型号参数加载。
- `include/t170/integration/dispatch/messages.h` 的默认调度地址用于日志/看板；实际 `Gateway::connect()` 只传型号和编号，真实网络连接还由厂商 SDK 管理，不能将显示常量当作实际连接配置入口。

建议在新 SDK 和动作稳定后逐项外置，保留单位、来源与有效性校验，不为了目录整齐一次重调数值。

## 需要准确理解的边界

- 公开技能已包含类型化请求、阶段、逐手结果、取消和持件证据；内部仍存在 `HwSession`、`move_box`、共享状态及 `skills/legacy` 兼容头，未完全消除旧结构。
- `src/config/effective.cpp` 负责快照/对比；通用参数解析仍在 `src/common/config.cpp`，伺服解析仍在 `src/servo/config.cpp`。
- 伺服 CSV 实现在 `src/common/servo_trace.cpp`；`src/telemetry` 主要负责调度事件、状态和控制台统计。
- 常规运动、IK 和伺服关节状态使用模型角；展示动作中保留设备角数据边界。原 `conveyor.h` 的 Motor radians 注释已更正。
- 新 SDK 源码调用链已切换，旧库仅归档。此处的离线 FK 后端测试不等于真实 Linux `.so` 已运行。
- No.124 选择 V2.0 3 kg，模型切换机制支持 5 kg；另一台机器人仍需自身设备绑定、工具和标定。
- 双手料盘抓取/放置四份旧参考不匹配新模型指纹，当前加载为 pending；原始记录保留，需重新确认保存。
- 传送带抓取当前开启手相机闭环；传送带放置默认仍是保留的开环路线，不应算作已实现视觉闭环。
- 运行目录通过源码树 overlay 和单机标定目录链接组织；依赖源码，不具备独立可搬运发布包的性质。
- `packaging/cpack/`、`packaging/deb/`、`.github/workflows/` 当前仅有 `.gitkeep`；依赖还未完整锁定，设备/底盘/调度等实现仍依赖机器人 `/opt` 安装。
