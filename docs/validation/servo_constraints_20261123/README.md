# 双臂构型选择与在线动态约束

日期：2026-11-23。基于现场日志提交 `4c65b78`，修正右臂腕部贴限位、在线半步限幅导致低速，以及异常关节反馈触发 Z 保护的问题。抓取和放置共用构型预检查及在线求解，准备位、标定和竖直撤离复用更新后的自然姿态策略。SDK 二进制、MDH、工具、模型角转换、硬限位与固定 Home 目标保持原值。

## 1. 反馈有效性

`read_joint_feedback` 按手臂串行读取完整七轴帧，完成设备角到模型角转换后，检查有限值、有效范围及与上一有效帧的连续性。连续性允许量为 `0.02 rad + 2 × 模型速度上限 × 时间间隔`；反馈范围额外允许 0.02 rad 的读数裕量，命令仍使用严格有效限位。零角本身不作为拒绝条件。

读数失败或跳变时最多完整重读三次，重读间隔 1 ms；无效帧不替换输出，也不更新滤波器的上一有效帧。原始关节数据及恢复计数通过 `[joint_feedback]` 写入终端日志。

视觉伺服遇到短暂读取失败时保留上一有效状态及其原时间戳，跳过本次控制更新；不将旧数据伪装为新采样，也不写入速度、相机变换和观测历史。超过 100 ms 未恢复有效反馈时，按反馈故障退出。零值究竟来自设备 SDK、通讯还是缓存状态，仍需底层返回有效标志与时间戳才能进一步区分。

`differential_ik_test` 读取本次真实 CSV 的右臂控制记录，拦截同一坏帧的两条记录，并确认前后正常数据继续通过。`arm_io_test` 用原 IO 适配函数注入四轴归零，验证完整重读、输出不被覆盖以及恢复行为。

## 2. 肘部与腕部策略

自然姿态保留肘部目标、关节偏好和限位回避，并新增腕部舒适余量评分。肘部方向由向下与本侧向外共同确定；外展比例从 0.5 调为 1.0，左右使用同一镜像规则。评分同时抑制向躯干夹肘和明显抬到肩部上方，允许外展时上臂接近水平。

候选搜索增加肩部展开、上臂旋转和前臂构型的确定性初值，覆盖现场原先四个近邻种子未充分探索的区域。评分包含肘部偏差、向外展开区域、腕部余量、起点连续性和较弱的 Home 距离。显式固定 Home 不在线重新选解。

连续直线沿整条路径建立关节参考和连续肘部参考；肘部与腕部软目标保留较弱的局部权重，避免每毫米重新追逐独立最优肘点而产生波纹。在线阶段将肘部、腕部偏好放入同一个速度 QP，不再用原先约 `10⁻⁵ rad` 的逐周期零空间上限作为主要姿态调整方式。没有 TCP 运动请求时，次级速度也收缩，避免持续姿态漂移。

外置字段位于 `config/robot_models/t170c_v2_3kg/motion_policy.yaml` 及 5 kg 同名文件：

| 字段 | 当前值 | 含义 |
|---|---:|---|
| `elbow_outward_ratio` | 1.0 | 向外相对于向下的偏好比例 |
| `elbow_clearance_m` | 0.08 | 肘部相对肩部向外展开的软目标 |
| `wrist_margin_rad` | 0.14 | 腕部舒适余量，约 8° |
| `wrist_gain` | 2.0 | 腕部靠近边界时的软代价 |
| `elbow_gain` | 8.0 | 肘部偏好基础权重 |

这些是软目标，不是“余量不到 8° 就失败”的新门限。实际不能兼得时，求解仍以末端任务和有效硬限位为约束。运动学偏好不代替完整的机身、夹爪和环境碰撞模型。

## 3. 整段操作的构型预检查

新增 `Arm::Approach_Stroke(start, guide, finish, ...)`：为引导点生成候选构型，在每个候选上沿引导点到操作终点连续求解，评价全段姿态代价、最差姿态与关节路径长度。选择构型后生成接近轨迹，并从实际生成的接近终点再次复核操作行程；若接近或复核失败，尝试下一候选。预检查失败不保留可误执行的半段轨迹。

视觉伺服抓取、放置和传送带动作共用该入口。非视觉两段接近也接入相同预检查；竖直退出专用分支仍保持原来的退出路径约束。准备位与标定接近使用更新的通用逆解和转场；竖直撤离使用保留肘部参考的共用直线规划；关节 Home 继续执行固定目标。

预检查验证的是名义行程的连续几何可行性与姿态质量。实际视觉修正发生后，每个周期仍须重新满足在线动态约束，不能把一次预检查当作后续所有修正的可行性保证。

## 4. 统一在线速度 QP

`src/motion/differential_ik.cpp` 直接求解七轴速度 `v`，再按实际控制周期积分 `q_next = q + dt × v`。目标由 TCP 位置/姿态速度及零空间肘部、腕部偏好组成。

同一个问题中同时施加：

- 有效模型/驱动关节范围：`(q_min-q)/dt ≤ v ≤ (q_max-q)/dt`。
- 关节速度：`-v_max ≤ v ≤ v_max`。
- 关节加速度：`v_prev-a_max×dt ≤ v ≤ v_prev+a_max×dt`。
- 接近关节限位时的制动距离约束，包含当前积分周期的距离预算。
- TCP 安全 Z 平面的线性约束与制动速度界，积分后再检查非线性 FK 残差。

关节约束通过七变量有界 QP 求解；Z 平面通过拉格朗日乘子求解，同时保留所有关节约束。原来“先求位置、检查不通过再试 1/2、1/4……”的正常控制分支已删除。实际推进速度反馈给控制器，但不再经过固定比例二分限幅。

在线速度和加速度仍取视觉伺服上限与模型上限的较小值，当前分别为 0.45 rad/s 和 2 rad/s²。位置范围仍来自统一有效限位。旧相对 B 点 0.7 rad 的窗口不再附加在该动态求解器上；正常运动由有效范围、每周期动态约束及已有 TCP 工作约束控制。

在线 QP 本次约束位置、速度和加速度，未新增在线 jerk 硬约束。离线转场、直线与关节回程继续检查原有采样速度、加速度和 jerk 上限。平滑交接的关节速度条件由原来约 0.01 rad/s 改为正常伺服速度上限，接管后承接上一段速度，保留 TCP 交接速度及姿态条件。

约束形式参考 [Pink 的加速度与制动距离实现](https://github.com/pink-kinematics/pink/blob/main/pink/limits/acceleration_limit.py)及 [QP 构建流程](https://github.com/pink-kinematics/pink/blob/main/pink/solve_ik.py)。本项目使用独立 C++ 实现，不新增 Pink、Pinocchio、Python QP 或 ROS 2 运行依赖。

## 5. 验证结果

自动测试共 47 项：44 项离线回归和 3 项本机 HTTP/网页测试。生产运动、技能、应用及 SDK 适配源码完成离线编译检查；未连接机器人或在 macOS 上执行 Linux SDK 二进制。

`arm_stroke_test` 覆盖 20 个完整闭环工况：3/5 kg、左右臂、最近排抓取的 ±60° yaw、料盘放置的 ±50° yaw、放置 B 点观察虚拟邻孔目标后下降，以及传送带代表姿态。其中 8 个工况增加 180 ms 的一阶关节跟随滞后；并检查抓取后竖直退出、关节回程与不可达终点拒绝。控制周期交替使用 9/11 ms，逐周期检查速度、加速度和有效限位。

本次 No.124 右手失败目标的模型回归结果：

| 工况 | 接近段名义时长 | 接管到完成 | 最小腕部余量 | 最小肘部外展距离 |
|---|---:|---:|---:|---:|
| 3 kg 右手抓取，理想跟随 | 2.730 s | 2.471 s | 6.81° | 152.7 mm |
| 3 kg 右手抓取，180 ms 跟随滞后 | 2.730 s | 2.480 s | 6.81° | 152.4 mm |
