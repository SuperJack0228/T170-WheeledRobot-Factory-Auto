# 第二批与第三批运动恢复说明

日期：2026-11-23。基于 `deployment1117` 分支 `fc310f8`，保留第一批网页、配置读取和失败结果修复，调整准备位转场、视觉伺服前伸手、固定姿态直线和标定微调。SDK 二进制、3/5 kg 模型几何、电机方向零偏、固定 Home 和现有运动上限未修改。

本批已完成源码编译检查、45 项自动测试及 52 个模型轨迹工况。本文中的轨迹时长均为离线规划值，不包含驱动跟随、到位等待、夹爪和视觉耗时；尚未连接机器人执行。

## 1. 慢动作的来源

现场 `startup.log` 包含右臂约 20.12 s 的抬升、17.825 s 的平移、多次 32～37 s 的伸手/接近。相应规划本身仅耗时约十几毫秒，主要等待发生在生成的轨迹播放期间。

用现场四舍五入后的模型角、当前 No.124 的 3 kg 几何及工具、现场有效限位重放旧算法，可复现 20.135 s、17.905 s、32.980 s 的慢轨迹。原路径在每个约 1 mm 的笛卡尔点重新叠加肘部、偏好姿态和限位回避，七轴冗余分配产生细小波动；这些波动在三阶差分中被放大。时间规划满足 jerk 上限时，会将整段轨迹显著拉长。准备动作又把抬升、平移、校正 Z、转腕分开执行，进一步增加时间和停顿。

因此本批先改善路径，再安排运动时间。仅提高 TCP 速度参数无法消除不平顺路径触发的全局减速。

## 2. 第二批：转场和连续路径

### 自由空间转场

新增 `Arm::Approach_Trajectory`：对目标 TCP 位姿求一次七轴逆解，采用关节空间静止到静止轨迹，同时完成位置和姿态变化。原有肘部偏好用于目标构型选择，正常调用不锁 J2。

关节轨迹逐样本检查有效限位和 TCP 转场范围：不明显低于起终点中较低的高度，XY 不超出起终点范围两侧各 30 mm，向上不超出较高端 50 mm。超过该范围时，在发送动作前改用经过检查的笛卡尔直线；不会先走一段再临时换路。该检查是转场范围检查，不代替全身或环境碰撞模型。

准备位动作保留低位竖直退出，以及确有需要的本侧分区退出；之后将平移、Z 和转腕合并为一次转场。左右臂均完成路径预检查后再并行执行。准备位保留原有 50 mm 位置容差，并复用 5° 姿态容差，并在共用执行器内确认 TCP 反馈稳定；没有把标定的亚毫米门限套到准备动作上。原有垂臂姿态分支保留。视觉伺服 A→B 的伸手接入同一转场方法，后续连续交接和下降修正继续使用既有伺服控制器。

### 固定姿态直线和竖直退出

`Arm::Line_Trajectory` 在整条路径上建立连续参考构型，由上一点关节角连续求解。较长路径预先选择目标构型；短距离微调优先使用当前位置附近的解，避免小幅 TCP 调整伴随大幅冗余关节调整。各路径点仍求解带关节增量上下界的七变量 QP，主任务仍是 TCP 位姿。

对连续 IK 路径进行自适应控制点稀疏化，再使用凸包保持的 C2 B 样条和五次时间标度。依次尝试较稀疏到较密集的控制点，并逐输出点检查约 0.5 mm 的直线偏差、5 mrad 的姿态偏差和有效关节限位；不满足时自动增加控制点密度。最终仍保留原有 1 mm / 10 mrad 直线复核。

完整采样流连同静止前后端检查速度、加速度和 jerk，另行检查 TCP 峰值速度不超过调用方指定速度。抓取后的竖直抬升也复用该直线规划，继续保留实测抬升进度回调、腰部联动和退出高度条件。Home 仍执行固定七轴目标，不重新选解。

### 保持指令的交接

准备位和视觉伺服前伸手从上一段仍在保持的命令关节角开始规划。不会把尚有跟随滞后的编码器角直接当作新命令起点，避免额外连接段或保持交接拒绝。实际到位仍通过编码器反馈判断。准备位执行器和闭环下降已经完成到位判断后，仅记录 TCP 快照，取消随后重复执行的通用停稳等待；旧等待默认每侧最长 15 s。非闭环播放仍保留实际到位等待，超时会向上返回失败。

## 3. 第三批：标定接近与微调

标定准备、观察点接近使用转场规划；B→D 下降和 D 点微调使用固定路径的直线规划。准备位速度请求从 0.10 m/s 调整为 0.35 m/s；观察点接近仍为 0.35 m/s，下降仍为 0.18 m/s，微调仍为 0.04 m/s。请求速度是上限，短位移仍需按加速度、jerk 限制完成起停，不要求瞬间达到该速度。

移除独立的 10 ms 逐点求解、反复将时长乘以 1.7 的微调实现。标定接入共用的 5 ms 轨迹执行器、20 Hz 编码器反馈和异步 CSV。路径预检查缓存另一只手的位置，不在每个路径点重复查询 CAN。

到位判断同时检查 SDK FK 所得 TCP 位置、姿态以及连续反馈的稳定程度。普通标定接近的位置容差为 2 mm；不超过约 5 mm 的微调采用请求位移的 15%，限制在 0.03～0.75 mm。执行器还需连续满足稳定样本要求。该容差仅用于标定，不收紧生产抓取的合爪门限。

现场曾出现目标 X 增加约 5 mm、实际仅移动约 0.7 mm，却被 `±550` 编码器带判定停稳的情况。新增回归模拟了粗关节带会误判的微调，并验证 TCP 门限拒绝误报、滞后模型最终正常到位。超时返回失败并保持实测位置；标定会话中断也可中止共用执行器。

这里的 TCP 反馈来自编码器和运动学模型，不能独立证明真实夹爪在工厂坐标中的绝对精度。真实手眼误差和结构变形仍通过现场图像及实际抓放验证。

## 4. 离线结果

同一组现场模型角起点、同一组目标的代表性比较：

| 工况 | 旧算法重放 | 本批规划 | 当前用途 |
|---|---:|---:|---|
| 右臂低位竖直抬升 | 20.135 s | 1.510 s | 保持 TCP 姿态的直线 |
| 右臂到准备位 XY | 17.905 s | 2.745 s | 自由空间转场 |
| 右臂伸向目标上方 | 32.980 s | 2.560 s | 自由空间转场 |
| 同一右臂伸手目标，明确要求直线 | 32.980 s | 5.865 s | 保留直线路径的对照 |
| 左臂伸向目标上方 | 1.850 s | 1.185 s | 自由空间转场 |

右臂标定观察点接近约 3.905 s，随后约 110 mm 的固定姿态下降约 3.200 s；0.2～5 mm 微调的名义时长约 0.25～0.415 s。两个标定阶段仍在观察点衔接，尚未改为整段不停顿穿越 D 点。

52 个工况覆盖 3/5 kg、左右手、Home→准备位、抬升、X/Y 正向微调、现场 D 点正负微调、现场起点 ±0.1° 扰动、关节转场和直线对照。全部工况的关节速度峰值不超过约 0.888 rad/s，加速度不超过约 2.171 rad/s²，jerk 不超过约 19.55 rad/s³；现有上限分别为 0.9、2.5、20。输出曲线检查使用静止前后端差分。

5 kg 工况为名义 260 mm 工具及保守有效限位下的模型计算，不代表 5 kg 机器人的现场限位或带载测量。轨迹曲线不包含驱动内部插补和实际机身柔性，实机速度与抖动需据反馈日志确认。

## 7. 机器人更新与观察顺序

停止旧主程序，在机器人当前仓库编译并启动：

```bash
cmake -S . -B build_robot
cmake --build build_robot --parallel 2
unset T170_ROOT T170_CONFIG_DIR T170_RUNTIME_DIR T170_DEPLOYMENT
./deploy/run_maintenance.sh 2>&1 | tee startup.log
```

网页继续另开终端运行 `./deploy/run_web.sh`，沿用第一批恢复后的界面。

先观察双臂固定 Home、料盘准备位，再验证标定观察点与 D 点、0.2/2/5 mm 微调。若启动报告 `calibration_pending`，先完成被模型指纹作废的抓取/放置标定，再验证单次双手料盘抓取与竖直退出、传送带抓取。准备位和伸手应主要在数秒级完成，具体时间叠加实际跟随和到位反馈。若名义时长正常而 `elapsed_s` 显著增加，优先看跟随差与反馈耗时；若 `nominal_s` 本身过长，保留该工况起点、目标和 `[arm_path]` 继续检查路径。

保留 `startup.log`、本轮 runtime 的 `logs/arm_limits.yaml` 和 `logs/visual_servo/servo_*.csv`。无需再次手改 Home、J2 或关闭有效限位来测试本批修改。

## 8. 方法参考

[MoveIt 时间参数化官方说明](https://moveit.picknik.ai/main/doc/examples/time_parameterization/time_parameterization_tutorial.html)将几何路径与速度、加速度及后续 jerk 平滑分开处理。[Ruckig 官方文档](https://docs.ruckig.com/)给出了受速度、加速度、jerk 约束的状态到状态轨迹生成方案。本批沿用项目内的边界 QP、C2 路径和五次时间标度实现，通过逐采样流校验运动上限，没有引入 Ruckig、TOTG 或 ROS 2 运行依赖，也不将当前实现称为时间最优规划。
