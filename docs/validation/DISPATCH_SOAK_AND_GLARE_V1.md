# 第一阶段：调度连续运行统计与传送带二抗反光

日期：2026-11-12。基于 `wrist-servo` 的现场提交 `43e1e66`。本次没有改变调度协议、任务分配、审批语义或电机运动限制。

## 现场版本和已有证据

最新提交新增了现场抓取/放置标定、传送带下降速度、夹取后收手与工位间协同调整、相机曝光/增益处理。沿用这些现场改动。

重点核对了最近五份传送带二CSV：`servo_1794401772017682_128651.csv`、`servo_1794402004819158_131005.csv`、`servo_1794402355896780_134287.csv`、`servo_1794402491918300_135449.csv`、`servo_1794402670189863_136723.csv`，包含7个伺服会话。可见大量 `locked_target_missing`、`waiting_fresh_vision` 和目标丢失类终止。部分会话只有1–5次accepted，不等于根本没有图像。没有上传对应RGB图像，无法用实图证明拟合效果；90%为现场描述，不当作由这7个会话统计出的成功率。

## 传送带二的几何回退

只在明确标记为 `belt2_grasp` 的会话中启用。普通料盘、传送带一、标定不进入这条回退。原料盘/传送带参考点的现场复用方式保留；不修改其已标定数值。

1. 同一帧先跑原YOLO。类别、置信度、目标关联均有效时直接使用原结果。
2. 没有有效目标框或YOLO异常时，使用该帧RGB和拍摄时刻插值的实际TCP/相机位姿。不取深度。
3. 用原任务位置与参考模型预测目标所在区域，限定搜索范围，不在整图随意找圆。
4. 使用固定的零件顶面平面，把局部区域直接重映射到去畸变的度量平面。图像中的椭圆在这里恢复成圆，避免直接拿透视椭圆中心当真实圆心。
5. 排除饱和区域及其边界，对剩余边缘进行RANSAC圆拟合并用内点重估。顶面外径约27mm，采用13.5mm半径先验；同心内孔不能当作任意尺寸候选。
6. 检查外圆半径、距任务预测位置的距离、径向残差、至少8/16角度分区覆盖、内点数量和多个中心的歧义。只剩短圆弧、全白、背景或多个同等可信中心时不输出伪定位。
7. 拟合中心重新投影回原彩色图，标记 `vision_source=belt_circle`，进入原有时间戳校验、运动延迟补偿、PD、制动和合爪确认链路。YOLO下一帧恢复后仍优先YOLO。
8. 两种定位都无证据时仍按原流程等待并有界超时，不绕过检查、盲降、无限重试或强制合爪。已有近底部的目标冻结逻辑保持原样。

外置参数在 `visual_servo.belt2_circle`。`radius_m=0.0135` 来源为现场提供的约27mm外径；可在实测后调整，不能用旧视觉配置中的 `0.0275`（它是半径）。搜索半径25mm、拟合残差1mm、最少半圈角度覆盖是首版初值，需实图回放/真机验证，不是工业精度保证。

`feature_above_final_m` 是**零件顶面相对最终TCP的Z差**，不是相机深度。默认0与当前抓取映射平面一致；如果顶面实际高于TCP 10mm，应按实际工具/抓取定义填写0.010，不能直接拿料盘高度替代。该参数对YOLO映射与几何回退同时生效，避免来源切换时平面不一致。

`max_time_ms=60`是单次回退计算预算上限，不是主动等待60ms。新观测仍须通过原新鲜度限制。先看日志实际 `geometry_ms`；不要遇到过期就不断放宽门限。

原CSV新增：`geometry_radius_m`、`geometry_residual_m`、`geometry_coverage_bins`、`geometry_inliers`、`geometry_ms`、`saturated_fraction`；记录每次回退尝试、成功/拒绝原因及其后控制器是否accepted。调试图标注当前来源。抓取观测先提交给控制器，再由有界后台队列编码/保存调试图，避免存图使检测结果过期；开启原图采集时另存原始PNG及拍摄位姿/内参。

### 首次实机验证

先用原二号传送带单手抓取指令验证，TCP和工位高度保持现场设置。分别记录：YOLO框缺失时是否进入circle、拟合点是否在真实顶面圆心、是否被控制器接受、最终是否实际夹住及离站。再测另一只手和双手。两个来源都有结果时特别检查中心是否系统性不一致。

如果仍失败，提供对应完整CSV与该次原始RGB/调试图。当前仓库只有相机侧参数及日志，缺少这批反光原图，离线不能判断可见圆弧是否足够。

## 调度结构化统计

直接启动原调度入口即可，`T170_TIMING`默认2：

- `0`：关闭；`1`：运行、任务、步骤和业务事件；`2`：再加细相位。
- 新日志：`$T170_LOG_DIR/dispatch_metrics/run_<运行ID>.jsonl`；未覆盖时为 `logs/dispatch_metrics/`。
- 同名 `_config/` 目录保存本次参数、相机、手眼、工具模型及标定副本。日志记录构建提交（含dirty标记）、机器人、服务端、UTC时间和单调时钟耗时。
- 每次进入调度新建运行ID，每个任务独立任务ID。细相位在开始时捕获所属任务，避免并行线程跨任务后把耗时记到下一任务。
- 有界队列异步写盘，控制循环不直接刷统计文件；正常结束排空队列。记录丢弃事件数和写入状态；掉电/强杀时报告将运行或任务列为未结束。
- 原详细servo CSV仍保留。结构化 `servo_start` 指向CSV和session；`servo_end`汇总持续时间、手臂、accepted来源、拒绝/缺失/过期计数及终止原因。
- 记录任务返回码、步骤耗时、导航/申请等待/头相机感知总耗时/伺服下降/夹爪开合/竖直抬升/关节收手细相位、空抓反馈、抓取尝试、视觉重试、调度异常解决、料盘取放件计数。

### 成功率口径

- **程序任务完成率**：任务最终报告success / 全部已开始任务；未结束任务不当成功，也另列计数。
- **首轮完成率**：最终success，且没有记录到重试、外部异常解决、伺服失败、空抓、未知夹爪反馈或失败抓取尝试。几何回退是正常观测来源切换，不当作任务重试。
- **恢复后完成**：程序最终success，但发生过上述异常事件。不得与首轮成功混在一起宣传。
- **无人成功率**：没有完整人工干预记录时保持未知，不把“程序继续运行”当作没有人帮忙。
- **实物成功率/合格率**：现有夹爪与程序反馈不能独立验证放入正确孔、掉件或加工质量。需人工抽检/录像或新增外部确认单独统计。
- **吞吐**：程序报告放入料盘二的件数 / 已正常闭合运行的墙钟时长，包含等待。开放运行时暂不计算，不能把各个并行阶段耗时相加当总时长。
- 同时输出P50/P95、任务类型分组、首轮/失败/未结束、伺服来源、失败原因和按手臂的执行结果；成功率附Wilson 95%区间。步骤/细相位统计包括失败样本，成功任务耗时只使用成功任务。

人工干预可额外保存独立JSONL，再用 `--annotations` 合并（不要并发改机器人正在写的原日志）：

```json
{"type":"manual_intervention","run_id":"对应运行ID","mission_id":"对应任务ID","mission":"对应任务类型","detail":"扶正零件后继续"}
```

未提供完整人工记录时，报告不计算无人成功率。现场人员至少记录：是否扶正/补料、是否人工松合爪、是否重启/复位、是否通过Web或终端改参数，以及时刻、任务ID和原因。

## 连续试验顺序

1. **抗反光单工位验证**：单手再双手，核对回退圆心与实物结果，不能直接用客户演示代替首测。
2. **调度短循环**：保留现有调度流程，先做若干完整上料→转运→下料循环，核对任务ID、返回码、统计件数与实际件数，检查双手/并行动作耗时归属。
3. **连续1–2小时**：记录每次自动恢复和人工干预。保留全部失败任务；按任务类型分别统计。每种任务样本数太少时，不宣称高成功率。
4. **连续4–8小时**：在短循环已通过后进行。观察曝光/照明变化、镜头污染、CPU温度/负载、推理耗时、剩余磁盘和网络等待。中断测试也保留日志，不只挑选一段顺利的时间。
5. **第一阶段报告**：写清机器人/版本/参数、实际试验时长、各类任务数、首轮完成和恢复后完成、实物抽检、人工介入、主要失败模式、P50/P95节拍和验收边界。样本量与置信区间一起呈现。

开始长测前关闭连续调试存图：`visual_servo.tray_place.save_debug_images: false`，不要开启 `hand_descent_raw`；抗反光定位阶段可先保持存图用于诊断。大量每帧JPEG既影响时延又占磁盘。结构化统计与详细servo CSV不受此存图开关影响。日志不自动删除，测试前预留容量，测试后归档。

## 报告生成

报告工具只需Python标准库，不安装绘图库、不联网：

```bash
python3 tools/dispatch_report.py \
  --metrics logs/dispatch_metrics/run_*.jsonl \
  --out reports/dispatch_soak
```

可加 `--servo logs/visual_servo/servo_*.csv` 和 `--annotations annotations.jsonl`。不要用无关日期的大量CSV混成一次测试。

产物：`report.html`（独立SVG图表、统计口径和明细）、`summary.json`、`missions.csv`、`steps.csv`、`phases.csv`、`servo_sessions.csv`。CSV为UTF-8带BOM。正常运行、失败、未闭合运行、解析异常与日志丢失单列。复制的相同运行日志按run_id+seq去重。

只有旧servo CSV时可用 `--servo ... --out ...` 生成故障诊断页，但不会伪造不存在的调度任务成功率。首版历史诊断只用于展示这类数据，不是最终阶段验收报告。
