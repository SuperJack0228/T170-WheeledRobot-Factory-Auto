## 1. 这套新场景在做什么

现场现在有两条传送带，调试时底盘开到站就停住，不再为了换传送带再导航。

| 场景 | 底盘站 | 腰 | 认哪对码 |
|------|--------|----|----------|
| 传送带一 | 和料盘一都在 AP6。单独调试指令不导航，人把车停在传送带一旁边即可 | 先平移到 `x=-0.16, z=0.63`，再转到 **yaw -95°、pitch 20°** | 优先 `belt0`（左 0、右 3）。看不到 0/3 时，会用画面里先解出来的那条，所以 2/4 也能用上 |
| 传送带二 | 和料盘二共用 **AP7**。调试指令不导航 | 先平移到 `x=0.14, z=0.63`，再转到 **yaw 100°、pitch 20°** | **`belt2`：左 6、右 7**，都是 6×6 |

两条传送带的手臂准备位置、抓取流程是同一套，只是腰的朝向、前后位置、二维码和各自的 offset 不同。传送带二是从传送带一抄过来再改数字的。

坐标系：手臂基座和二维码都是 **+X 前、+Y 左、+Z 上**。腰回转向左为正。

## 2. 怎么启动、怎么发指令

程序只听本机 `127.0.0.1:8099`。另开一个终端发指令：

```bash
cd /home/ti5robot/T170Clean
python3 tools/debug_client.py belt2_grasp
```

客户端在 `tools/debug_client.py`。进程标准输出如果是用 `tee` 记下来的，在 `startup.log`。标注照片在 `picture_debug/head/`。

客户端报 `Connection refused`，表示 `t170c_debug` 没在听 8099，先把控制进程拉起来再发。

旁边留人，手里有实体急停。软件 `abort` 只是让流程尽快停，不能代替急停，也杀不掉已经卡死的进程。客户端 Ctrl+C 只断自己这一条连接。

```bash
python3 tools/debug_client.py abort
```

### 改了什么要不要重启

| 改了什么 | 怎么生效 |
|----------|----------|
| `config/move_box_params.yaml` 里的数字（腰角度、tcp、offset、悬停高度） | `python3 tools/debug_client.py reload` |
| `board_belt_aruco/config.yaml`（码的 ID、字典） | 必须重启 `t170c_debug`。reload 不读这个文件 |
| `config/Robot_Arm_Model.yaml`（手臂模型、软限位） | 必须重启 |
| 任何 C++（`src/`、`orchestrator/cpp/`） | 先编译，再由人重启进程。reload 不够 |

编译：

```bash
cmake --build /home/ti5robot/T170Clean/build_robot -j2 --target t170c_debug
```

不要在别人没准备好的时候启动 `t170c_debug`，它会动真机。

## 3. 调试指令：每条做什么、不做什么

下面这些是**现场单步调试**。它们都不导航，底盘停在原地。

### 传送带一

| 你输入的命令 | 实际做什么 |
|--------------|------------|
| `belt1_waist` | 腰先平移到拍照 `x/z`，再转到 -95° / 俯仰 20°，头低到 10°，双手收到准备 `tcp`。用来把腰和手臂摆到观察位 |
| `belt_ready` | 腰、头、准备 `tcp` 到位。不拍照、不放、不抓 |
| `belt_grasp_rpy` | 腰和头同准备位，手臂走到准备 `tcp` 的 XYZ，但手腕用 `grasp_rpy_deg`。不拍照、不夹爪。用来先看抓取姿态够不够得到 |
| `belt` 或 `belt_place` | 先摆腰，再拍照认码，右手放完再左手放，然后回到准备 `tcp`。不夹取来料 |
| `belt_grasp` | **不再摆腰、不导航**。人已经在观察位时原地拍照，手臂先到准备 `tcp`，再抓。抓完停在准备 `tcp` |

### 传送带二

和上面一一对应，参数读 `conveyor2`：

| 你输入的命令 | 实际做什么 |
|--------------|------------|
| `belt2_ready` | 不导航。腰平移到 `x=0.14`，再转到 yaw 100° / pitch 20°，头 10°，双手到 `conveyor2.tcp` |
| `belt2_grasp_rpy` | 不导航。腰和头同观察位，手臂停在 `tcp` 的 XYZ + `grasp_rpy_deg`。不拍照、不夹 |
| `belt2` 或 `belt2_place` | 不导航。先摆这段腰，再认码放置 |
| `belt2_grasp` | 不导航、不再摆腰。原地拍照后抓，收手回到 **这一套的准备 `tcp`**，不是 `grasp_tcp` |

建议顺序：

1. 车已经停在 AP7、传送带二对着机器人时，先 `belt2_ready` 或 `belt2_grasp_rpy`，确认腰能平移再转过去，手能到准备位置。
2. 姿态看起来对，再 `belt2_grasp`。它假设腰已经在观察位，不会自己再转腰。
3. 放置用 `belt2`。它会自己先摆腰再拍照。

### 不要和下面这些整圈指令搞混

这些会导航，调试传送带二时先别发：

| 命令 | 含义 |
|------|------|
| `cycle` 或 `grasp_belt` | 演示整圈，不跟调度要任务。先确认人在 AP6 的料盘抓取姿态，再：料盘抓 → 升腰、转腰弯腰 → 传送带一放 → 传送带一抓 → 去 AP7 的同时摆传送带二 → 传送带二放 → 传送带二抓 → 起身转正 → 降腰料盘放。然后下一圈，直到 `abort` |
| `cycle1` | 只在 `cycle1.station`（现在是 **AP6**）上循环料盘抓和传送带一放。底盘只去这一站 |
| `cycle3` | 传送带二抓（`out_station`，现在是 AP7）→ 料盘二放（`tray2_station`，现在也是 AP7）。放完停住，不升腰 |

站点在 `config/move_box_params.yaml` 最下面的 `chassis:`：

| 配置名 | 现在的站 | 用途 |
|--------|----------|------|
| `tray_station` | AP7 | 料盘抓取 |
| `belt_station` | AP6 | 传送带一。现场没有 AP5 |
| `out_station` | AP7 | 完整循环里的传送带二 |
| `tray2_station` | AP7 | 料盘二，和传送带二同一站 |
| `cycle1.station` | AP6 | `cycle` 和 `cycle1` 的第一站：料盘抓、传送带一放和抓 |

底盘地址 `192.168.192.5`。

## 4. 一条抓取、一条放置实际怎么动

两条传送带共用这一套动作，只是读的 yaml 段不同。

### 抓取（`belt_grasp` / `belt2_grasp`）

1. 原地拍一张头相机的照，认 6×6 码。
2. 抓取点 = 码原点 + 识别坐标系下的 `grasp_offset`。不随腰的转角再乘一次 Rz。
3. 若开了固定高度（现在是开的），把这个点沿竖直方向落到标定水平面。传送带高度不跟相机深度走。
4. 手臂先到准备 `tcp`。
5. 从旁边抹一个小圆弧到抓取点，**不在抓取点上方停车**。
6. 到位停 0.5 秒，再合爪。
7. 合爪后沿世界竖直方向抬起 `grasp_hover_above_m`（传送带一 6 cm，传送带二 8 cm），中间不停，接着平移回准备 `tcp`。平移时先保持抓取时的手腕角度。
8. 若准备 `tcp` 的手腕和抓取手腕差超过约 2°，到位后再以 40°/s 慢慢转腕。这一步会带着手臂一起动，看起来像多转了一下。要消掉它，把该手 `tcp` 的后三个角度改成和 `grasp_rpy_deg` 一样。
9. 左手已经夹到之后，右手马上过来，不等左手完全收回。

`grasp_tcp` 这组数**调试抓取用不到**。收手回的是准备 `tcp`。yaml 里「抓完回到 grasp_tcp」是旧注释。

### 放置（`belt` / `belt2`）

1. 先把腰平移到位，再转腰、低头。
2. 手臂到准备 `tcp`，拍照。
3. 放置点 = 码原点 + 识别系 `offset`。只用 `place_tcp` 的三个角度，不用它的 XYZ。
4. 抹角伸到放置点，不在上方停车。上方那一段高度是 `place_hover_above_m`（现在 6 cm）。
5. 停 0.5 秒，松爪。
6. 松爪后沿竖直抬约 3 cm，不停，直接回到准备 `tcp`。
7. 先放右手。右手放下后，左手再等 1 秒过来；右手同时抬起收回。

速度大约 0.15 m/s。

## 5. 手可以改的参数

主文件：`config/move_box_params.yaml`。  
`conveyor:` 是传送带一，`conveyor2:` 是传送带二。两边字段一样，数字各自一份。改完 `reload`。

位置单位是米，角度单位是度。六个数的手臂位姿是 `x, y, z, roll, pitch, yaw`。

### 腰和头

| 字段 | 传送带一现在 | 传送带二现在 | 含义 |
|------|----------------|----------------|------|
| `waist_x` | -0.16 | **0.14** | 拍照时腰前后位置。正值朝前。传送带二不要写成 0.16，见第 7 节 |
| `waist_z` | 0.63 | 0.63 | 拍照时腰高度 |
| `same_spot_yaw_deg` | -95 | **100** | 平移到位之后才转的回转角。向左为正 |
| `same_spot_pitch_deg` | 20 | 20 | 弯腰。0 表示不弯。腰转到 ±90° 附近时，这个俯仰大部分会落到侧倾电机上，人看到的前倾仍然大约是这个角度 |
| `head_yaw_deg` / `head_pitch_deg` / `head_roll_deg` | 0 / 10 / 0 | 0 / 10 / 0 | 头。俯仰 10° 是低头看皮带 |
| `grasp_waist_yaw_deg` | 0 | 0 | 抓取时额外转腰。现在是 0，不要为了过中线去转腰 |

到位判断：平移后的 `x/z` 和目标差超过 **2 cm** 就判失败，后面的转腰不会开始。日志是「腰未跟上」。

### 手臂

| 字段 | 含义 | 注意 |
|------|------|------|
| `tcp` | 准备姿态，抓之前和抓完都回到这里 | 左手 Y 必须为正。后三个数是手腕 |
| `grasp_rpy_deg` | 只有抓取时的手腕三个角 | 位置仍由码 + `grasp_offset` 决定 |
| `grasp_offset` | 识别系里，相对两码中点的抓取点。`x` 前、`y` 左、`z` 上 | 两手的 `y` 现在都是正的，也就是都偏左。右手若要抓皮带右侧，应改成负的 `y` |
| `place_tcp` | 放置时只用后三个角度；`belt_place` 预览才会走它的 XYZ | |
| `offset` | 识别系里的放置点 | 右手、左手的 `x` 故意错开，避免两件叠在一起 |
| `grasp_tcp` | 旧的抓完回程位 | **当前传送带抓取不读它** |
| `grasp_hover_above_m` | 抓取时从上方抹过去的高度，也是合爪后先抬起的高度 | 一号 0.06，二号 0.08。沿世界竖直，不是沿手臂自己的 Z |
| `place_hover_above_m` | 放置时从上方抹过去的高度 | 现在都是 0.06。松爪后的 3 cm 是程序里的固定值，不在 yaml |
| `grasp_ready_close_ratio` | 下探前夹爪先合上的比例。0 全开，1 全合 | 现在 0.35，避免碰到皮带边 |

传送带二当前手臂数字（和一号不一样的已标出）：

- 准备 `tcp`：右 `[0.55, -0.20, 0.05, -10, 30, 30]`，左 `[0.55, 0.20, 0.05, 10, 30, -30]`
- 抓取腕角：左 `[10, 30, -40]`，右 `[-10, 30, 40]`（一号右手是 `[−10, 30, 50]`）
- 抓取偏移：左 `x=-0.08, y=0.11, z=0.04`，右 `x=-0.08, y=0.11, z=0.03`
- 放置偏移：右 `x=-0.07, y=0, z=0.04`，左 `x=-0.13, y=-0.01, z=0.045`
- 放置腕角：右 `[-10, 20, 40]`，左 `[10, 20, -40]`

### 高度和识别开关

| 字段 | 现在 | 含义 |
|------|------|------|
| `use_fixed_origin_z` | true | 不用相机测到的皮带高度 |
| `fixed_origin_z_m` | -0.29 | 腰直立、腰高 0.63 m 时，肩到皮带约 29 cm。手臂 Z 向上，所以是负数。腰弯了之后，点会沿竖直落到这个水平面，前后左右会跟着俯仰变 |
| `prefer_belt` | 一号 `belt0`，二号 `belt2` | 优先用哪一对码。那对没看到，才用画面里另一对 |
| `grasp_yolo_enable` | false | 抓之前不跑 YOLO。定位始终用二维码 |
| `grasp_yolo_class_id` | 1 | 若打开 YOLO：1 半加工，2 精加工。只判断类别，不改位置 |

肩相对腰的高度在程序里按 **0.30 m** 估计，不是 yaml。腰弯着的时候，若抓取点整体偏高或偏低，先别靠这个数去凑，先看 `fixed_origin_z_m` 和 `grasp_offset.z`。

### 二维码

文件：`board_belt_aruco/config.yaml`。改完必须重启进程。

| 名字 | 左码 | 右码 | 字典 |
|------|------|------|------|
| `belt0` | 0 | 3 | 6×6 `DICT_6X6_1000` |
| `belt1` | 2 | 4 | 同上 |
| `belt2` | **6** | **7** | 同上 |

两码中心左右相距 10.9 cm。含白边 30 mm。只要看到其中一个码就能解位姿（`min_markers: 1`）。  
料盘仍是另一套 5×5，在 `board_yf100_aruco/`，和传送带互不影响。

启动日志里应能看到已加载的 id 列表包含 `0, 2, 3, 4, 6, 7`。拍照成功时日志会写 `belt2 ids=6,7` 这类字样。

### 不要手改、但会挡路的限制

- 手腕 J6 的机械限位大约 **±59°**。`Robot_Arm_Model.yaml` 里写成 ±90° 也不会放宽这颗关节。日志 `按住肘高走不到` 且返回 -3，多半是 J6 或腕奇异，把 `grasp_rpy_deg` 的偏航、俯仰改小，不要去放宽限位。
- 料盘工作高度上限 `grasp_valid.z_max: -0.05` 只约束料盘。传送带合爪后的抬起已经不再被它裁掉。

## 7. 中间遇到的问题，以及后来怎么处理的

### 7.1 肘一下抬高、一下放下

**现象：** 传送带放置时，手的起点和终点高度差不多，肘却在中途抬起再落下。

**原因：** 以前两个端点各解一次逆解，中间把关节角匀速插值。肩关节 J2 从大约 37° 插到 65°，肘就在空中画弧。代价函数还偏向把肘放低，所以下降段会换到一个更低的肘。

**现在的做法：** 直线大约每 3 cm 重解一次。每一小段都尽量把肘留在出发时的高度附近，J2 只在上一解的附近找。日志是「按住肘高 J2 … 肘高 a→b m」。  
若某一小段在限位内根本没有解，整段失败，日志是「按住肘高走不到该直线上的点」，并带上逆解码（-3 常见于腕或 J6）。  
这不是一套 14 轴的轨迹优化，只是沿直线把肘按住。准备、抓取、收回这些直线运动都走这一套。

### 7.2 右边二维码认不到

**现象：** 传送带一左边 ID 2 能看到，右边当时的 ID 5 没有。

**原因：** 不是配对写错。检测器用的是 6×6 字典，现场右边那张码是 **5×5 的 ID 5**。6×6 检测器看不到它。`min_markers: 1` 让只有左边一个码时也算出了位姿，所以看起来像「程序只认了一边」。

**处理：** 现场把右边换成 6×6 的 ID 4。配置里 `belt1` 右码改为 4。没有再加 5×5 检测。  
传送带二后来单独加了一对：**左 6、右 7**，仍是 6×6，`conveyor2.prefer_belt: belt2`。

### 7.3 抓取直接失败，或右手过不去

**现象：** `belt_grasp` 伸手抹角失败，日志 `ret=-3`，往往是左手或右手的 J6 已经顶在大约 ±59°。

**原因：** 当时两手的抓取 `y` 都是正的，右手要从自己一侧跨到和左手同一个点，再带着较大的俯仰和偏航，J6 没有余量。yaml 里的 J6 ±90° 不能越过机械挡块。

**处理：** 不放宽 J6。改 `grasp_rpy_deg` 和 `grasp_offset`，让直线上的每个点都有 J6 在 ±59° 以内的解。当前数字见第 5 节。以后再出现「走不到」，先看是哪一只手、目标 xyz 和三个腕角，把偏航往 0 收，或少给一点俯仰，然后 `reload`。

### 7.4 抓完收回时手腕又转一下，肘也跟着动

**现象：** 位置已经回到准备点，手臂仍慢转，J2、J3 和肘高一起变。

**原因：** 收回时先保持抓取腕角。若它和准备 `tcp` 的腕角差超过约 2°，会再以 40°/s 转腕。这一步重新解整条手臂，肘会被带下去。

**处理：** 把该手准备 `tcp` 的 roll/pitch/yaw 写成和 `grasp_rpy_deg` 相同，这一步会被跳过。程序没有强制改掉现有角度，因为手腕还在手调。

### 7.5 转腰失败，但电机没动

**现象：** 从 +95° 转到 -95° 时逆解失败，code=1，电机不动。

**原因：** 不是转到一半撞限位。规划把 -95° 折成了离 +95° 更近的 +265°，而软件限位是 ±180°，所以直接拒绝。1 号回转电机物理上也转不满 360°，不能从另一边绕过去。

**处理：** 最近的那一圈如果出了 ±180°，就改走限位里面的另一侧。+95° 到 -95° 会从 0° 经过，大约转 190°，不会去转 +265°。日志：「回转电机 1 不能绕圈，A° 出限位，改走 B°」。

### 7.6 腰突然剧烈旋转

**现象：** 在 AP7，传送带二要把腰从大约 `x=-0.16` 移到 `x=0.16`（约 30 cm）。移动过程中回转从 95° 被拧回 0°。

**原因：** 当时的前后平移用的是「直立直线」，它会把回转和侧倾拉回 0。30 cm 的平移和大幅度转腰叠在同一次运动里。

**处理：** 拍照前的平移改为保持当前转角，只改 `x/z`。平移被确认到位之后，才转到 `same_spot_yaw_deg` / `same_spot_pitch_deg`。日志应先看到「保持转角……先不转腰」，之后才是转腰。

### 7.7 平移到了，但腰仍不转

**现象：** 目标 `x=0.16`，实际停在大约 `x=0.12`，报「腰未跟上」，回转一直停在原来的角度。

**原因：** 踝电机（CAN ID 4）到 0° 就过不去。在腰高 0.63 m、俯仰 20° 时，再往前要踝再正一点点，电机停在 0°，腰最远大约只到 **x=0.12～0.14**。差超过 2 cm，程序不会开始转腰。膝和髋是到位的，不是整条腰没响应。

**处理：** `conveyor2.waist_x` 设在这个范围内。现在是 **0.14**。不要改回 0.16。若仍报「腰未跟上」，改到 0.12 再 `reload`。

### 7.8 抓完看上去没有抬起来

**现象：** 日志写了「抬 0.08 m」，手却像直接抽回去。

**原因：** 料盘允许的最高抓取高度是 `z=-0.05`。传送带抓取点已经在大约 `z=-0.03`，再抬 8 cm 会到大约 `z=+0.05`。旧代码把这个抬起点裁回 `-0.05`，和手指当时的高度差不多，等于没有先离开皮带。

**处理：** 传送带收手不再用料盘这道高度上限。抬起仍沿世界竖直方向，高度仍是 `grasp_hover_above_m`。重启新进程后，日志会打印 `抬 0.080m 到 xyz=(...)`，看里面的 z 是否明显高于合爪时的 z。

## 8. 看日志时这几句是什么意思

都在 `startup.log` 或跑 `t170c_debug` 的那个终端里。

| 日志 | 含义 |
|------|------|
| `不导航、不动腰，原地拍照后抓取` | 这是 `belt_grasp` / `belt2_grasp`，腰应保持你刚才摆好的角度 |
| `保持转角 yaw=… 先平移` | 正在前后移动，此时不应大幅转腰 |
| `腰未跟上 \|dx\|=…` | 平移没到 2 cm 以内，转腰被跳过。先把 `waist_x` 改到踝能到的位置 |
| `按住肘高走不到该直线上的点` | 这条直线中间某个点逆解失败。看同一段里是左手还是右手，以及 `ret=-3` |
| `手臂未到 tcp` | 规划执行了，但停稳后位置或姿态超出约 1.2 cm / 5° |
| `手臂到 tcp 失败` | 还没走到那一步，规划本身失败 |
| 客户端 `code=-5` | 上面某一段动作失败。具体原因在服务器日志，不在客户端那一行 JSON 里 |
| `ids=6,7` 且 `name=belt2` | 传送带二这对码认到了 |

客户端 JSON 里的 `grasped_left` / `grasped_right` 有时是上一轮留下的。本轮如果在伸手阶段就失败，不要用这两个标志判断这轮有没有夹到。

## 9. 接手时不要做的事

- 不要为了过点去放宽 J6，或把 J2/J3 限位再改松。
- 不要把传送带二的 `waist_x` 设到 0.16 以上。踝过不了 0°。
- 不要在平移函数里再改回「直立直线」，那会在转腰之前把回转拧回 0°。
- 不要把 `conveyor` 和 `conveyor2` 写成同一份数字。一号 yaw 是 -95、x 是 -0.16；二号 yaw 是 100、x 是 0.14。
- 改码的 ID 后如果只 `reload`、不重启，检测器仍是旧 ID。
- 不要把 `ARM_IK_ELBOW_WRIST.md` 当成当前肘部方案。当前行为以 `src/function.cpp` 里「按住肘高」那段为准。
