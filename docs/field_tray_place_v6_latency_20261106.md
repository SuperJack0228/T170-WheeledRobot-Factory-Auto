# 料盘放置 V6：缩短定位路径与修正双手时序

基于现场失败提交 `ff532c6`，日期2026-11-06。本轮修改针对11/06日志显示的计算延迟、观测间歇、恢复误触发和确认超时。机器人端耗时、物理放置精度与实际节拍仍待现场验证。

## 运行逻辑

1. 在B点获取可信孔位。首次仍做整体孔环发现与网格对应，保留行列身份、TCP修正范围等检查。
2. 正常跟踪优先使用上次有效且靠近目标的孔环，按目标周围方位分散选择，最多接受6个，最多扫描12个候选。孔环不足时可以使用原有相似模型/短时单孔跟踪，不用每帧遍历全盘。
3. 每帧统一生成橙色掩码和所选区域的平面校正结果，各孔从该结果取ROI。完整孔环先走快速拟合，不能通过时才对最多两个合理轮廓调用圆弧补全。已占用位置不再做无用的灰度warp/Canny；未占用位置只有在颜色几何失败时才使用灰度后备。
4. 镜头去畸变映射按各手相机的K、畸变和尺寸缓存；无畸变时直接使用原图。标定/尺寸变化会重建缓存。
5. 局部拟合残差超限时，允许剔除最多两个最差支持点并重新拟合，至少保留四个支持点；仍未通过原残差检查就拒绝该帧。单孔分支保留原有约束。
6. 已接受的静态目标允许支持短段连续XY修正。图像接收和下放确认仍要求新鲜度合格，电机反馈持续参与纠偏；不是每过600ms就立即在两帧间停车。
7. 实际XY进入4mm范围后，现场配置要求两个独立新帧、目标稳定、末端低速，并持续稳定80ms后才锁定下放。重复同一帧不能补确认数。最终C高度与原来的锁定后遮挡下放路径不变。

静态目标短时使用的前提是料盘、底盘和腰部在B点对准期间保持稳定。目标估计超过其有效期后仍会停止继续纠偏，不凭旧目标无限运动。

## 恢复和超时

- 观察线程发布独立的视野状态：明确缺少孔环/有效邻孔时才有资格触发一次20mm观察抬升。
- 图像迟到、拟合残差拒绝、计算繁忙、目标超出原运动范围，不等同于看不到孔，不再仅按“多久没有被接受观测”自动抬升。
- 接近目标且有近期进展或达标观测时，原6秒对准预算最多延长一次2秒。绝对上限8秒；始终没找到目标时不会因此无限等待。
- 丢帧后确认计数不再因为刚超过600ms就无条件清空；是否保留取决于静态目标有效期。新的观测误差超出允许范围，仍会清空达标确认。

## 时间戳与调试

放置观察线程已拿到拍摄时TCP状态，因此在提交前将其采样不确定度计入一次时间预算，并设置 `capture_timing_accounted`。控制侧识别该标记，避免重复叠加；抓取原有路径仍由控制侧补计。

有效观测先交给控制器，再构造调试叠加图；后台限频写盘仍保留。每只手每帧的日志新字段：

| 字段 | 含义 |
|---|---|
| `tray_undistort_ms` | 去畸变，包括必要时重建缓存 |
| `tray_acquisition_ms` | 本帧整体发现/网格对应，仅重新获取时有值 |
| `tray_prepare_ms` | 选点、共享颜色掩码、平面校正准备 |
| `tray_roi_ms` | 所选孔环提取总时间 |
| `tray_partial_ms` / `tray_partial_calls` | 圆弧后备的时间/调用次数；时间是ROI时间的子集，不能重复相加 |
| `tray_fit_ms` / `tray_pruned_neighbors` | 局部配准时间/显式剔除的弱支持点数量 |
| `submit_age_ms` | 提交前包含时间戳和拍摄状态不确定度的图像年龄 |
| `place_close_frames` | 4mm内的独立视觉确认数，区别于原2mm精确计数 |
| `static_goal_motion` | 当前在新帧间使用已确认静态目标纠偏 |
| `place_elapsed_s` / `place_deadline_s` | 对准经过时间/当前绝对对准时长上限 |
| `place_alignment_extended` | 是否已使用唯一一次有界延长 |
| `place_lock_blocker` | 当前为什么没有锁定下放 |

典型blocker：`waiting_initial_target`、`waiting_fresh_confirmation`、`xy_not_within_tolerance`、`waiting_independent_frames`、`goal_not_stable`、`arm_not_settled`、`observation_height_not_reached`、`waiting_confirmation_dwell`。开始延长预算时记录 `place_alignment_extension`。

正常调试图只标注本轮扫描/接受的少量邻孔。圈数变少是主动限制计算量，不等于整盘只识别出了这些孔。

## 外置参数和构建

`visual_servo.tray_place` 新参数：

```yaml
observation_age_s: 0.6
target_hold_s: 1.2
alignment_extension_s: 2.0
confirm_stable_s: 0.08
tracking_max_neighbors: 6
tracking_scan_limit: 12
```

`visual_servo.place_lock_frames` 现场配置为2；C++后备默认仍为3。XY容差、实际修正范围、固定C高度和碰撞/运动执行约束未借此扩大。

未指定单配置构建类型时，CMake默认 `RelWithDebInfo`（优化并保留调试符号）；显式指定Debug/Release会得到尊重。快照增加 `build_configuration`，便于核对现场是否使用优化编译。

机器人上更新完整代码和配置后，使用原构建目录重新编译：

```bash
cmake -S . -B build_robot -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build_robot --target t170_factory -j4
./deploy/run_factory.sh 2>&1 | tee startup.log
```

保留原有SDK/CMake参数和环境；以上配置不应覆盖现场另外指定的SDK路径。验证重点是左右手的 `submit_age_ms`、每阶段耗时、确认数和锁定阻塞原因，而非继续调大新鲜度。

## 离线验证范围

- 新增 `tray_place_latency_test`：提取 `servo_1793935479343615_18507.csv` 四组观测的真实到达/拍摄时序和时间不确定度，驱动合成闭环机械反馈。四组均能完成；另检查原6秒末尾才达标时可以有界确认、没有独立新图时不能下放、延长不能无限重试、可见但迟到的结果不会导致抬升。这不是旧物理轨迹或真机精度回放。
- 现有测试继续覆盖孔环定位、透视畸变、运动相机、部分孔环、未知孔位拒绝、双手执行与收手交接等。
- 增加完整孔环不调用圆弧随机采样、候选预算生效、配置快照保留新参数的检查。
- 实际运行时集成回归还覆盖拍摄状态时间不确定度只计一次，防止两级重复拒绝。

相同Mac、相同O3编译级别、相同合成输入序列的几何路径对比：完整孔环正常帧中位约39.5ms降至1.9ms；包含部分遮挡的帧中位约34.7ms降至2.0ms。两版均完成这组合成定位，新版使用6个有效孔环。它只说明重复计算显著减少，不能据此承诺T170上的毫秒数或实际成功率。

本轮没有声称解决“首次看到的全部都是短弧”的满盘初始化限制。整体定位仍要求足够可靠的初始信息；后续满盘专项应另行验证。
