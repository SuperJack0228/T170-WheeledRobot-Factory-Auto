基线公共组件改造已经完成，不占用后续三步的名额。后续三步为：

1. **底层模块归位与依赖整理**：vision、控制核心、硬件、运动学库、Python 包和基础观测/日志。
2. **动作任务拆分与参数独立**：运动执行、技能、任务、调度、应用生命周期，及分层配置/任务快照。
3. **资源收口与安装发布**：模型/SDK/工具/历史资料、环境和 CI、安装/打包/升级回滚及实机验收。

每一步可以包含多个小提交，先完成该步的本地检查再推进下一步实现。匹配 SDK 构建、资源补齐和实机验证可并行排期，尚缺时明确标记“已实现，待外部验证”，不能写成整步已验收。第三步定版前必须闭合全部发布门槛。代码迁移与算法优化分开；不在迁移中调 PD、偏置、限位开关和速度。

目录存在、离线测试通过、安装包生成，都不能单独证明实机抓放已验收。三步的工程成果目标是可构建、可安装、可打包、可追溯；正式 `v1.0.0` 还要求资源齐全、匹配 SDK 构建及定义范围内的实机验收。未满足时交付 `v1.0.0-rc.N` 并列明缺口。

后续步骤骨架里的 `.gitkeep` 仅用于让 Git 保存空目录；实际文件迁入后删除对应占位。没有创建假 YAML、权重、标定或实现文件。
