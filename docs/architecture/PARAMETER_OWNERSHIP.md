# 参数独立、标定与部署入口

本文件规定第二步必须实现的目标。当前新目录只有骨架；旧 YAML 和当前加载路径仍生效，不因本次规划切换配置。

## 七类内容分开

| 类别 | 目标位置 | 说明 |
| --- | --- | --- |
| 默认策略 | `config/defaults` | 控制/动作/运行策略的已验证默认值，可按明确白名单覆盖 |
| 型号规格 | `config/robot_models/t170` | DH、工具名义几何、关节/设备映射、腰模型和型号约束 |
| 工位/场景 | `config/sites/<site_id>` | 盘孔/码几何、站点、窗口、高度、工位姿态和流程差异 |
| 单机身份/设备 | `config/robots/<robot_id>` | 机器人 ID、相机 SN、设备连接、必要单机覆盖 |
| 标定结果 | `config/calibration/<robot_id>` | 手眼、头安装、TCP 实测校正、参考像素和实测映射 |
| 部署选择 | `config/deployments` | 显式选择型号、site、robot、标定版本和启动模式 |
| 运行状态 | 安装后的状态目录 | 持件、任务进度、占用、日志；不作为静态参数保存 |

当前真实机器人 ID 为 `TH-T170C-0124`，来自现有配置。site_id、标定版本和 SDK/环境版本应据实际填写；本轮没有编造这些值。

## 当前参数的归属清单

| 当前来源/内容 | 最终归属 | 第二步必须保持或核实 |
| --- | --- | --- |
| `move_box_params.yaml` 的 `visual_servo` 控制增益、速度/加速度、延迟、制动与观测门限 | defaults/control | 所有现有数值不因拆配置而重调；需覆盖时有来源记录 |
| 左右抓/放参考像素、图像旋转和高度相关映射 | calibration + 工位 profile 引用 | 关联相机 SN、分辨率、左图 180°、工具、抓/放类型和高度定义 |
| `feature_z_offset_m`、目标/可见平面等几何假设 | sites 的工件/技能 profile | 与标定映射区分，保留原定义及当前几何模式未实测的状态 |
| `head_grasp` / `tray2_place` 的动作速度、撤离和等待策略 | defaults/motion + site 技能覆盖 | 不改变共用抓放执行与原速度数值 |
| standby/home/ready、行姿态、近远排及腰部配合 | robot_models 的名义姿态 + sites 的场景姿态 | 区分型号参考与工位调试值，保存原坐标系与使用时腰姿态 |
| 整盘与逐行 XYZ 偏置、是否启用 | sites 的技能补偿；确属单机校正的进入 calibration | 保留原值、行号语义及 `use_row_offset` 状态；不因外置重新启用旧偏置 |
| `tray` 的固定高度、露出量、融合参数 | sites 的料盘几何/感知 profile | 区分几何高度与算法门限，保持腰高参考换算 |
| `grasp_valid`、左右分区、同时抓列差、前后排规则 | 型号工作范围 + sites 的选孔策略 | 工作包络和业务分区不再混为一个开关；保持原行为 |
| conveyor/conveyor2 的码选择、偏移、准备姿态、高度、速度和计数门限 | sites 的各 workcell | 每工位独立，复用同一算法；不复制整套代码 |
| 代码中的传送带窗口 `kBeltGraspWin*`、放置近邻距离等场景常量 | sites 的抓放窗口/检查参数 | 不仅迁 YAML；现有实际窗口值由代码抽取，不抄旧文档 |
| `chassis` 的站点、导航超时、待命/充电流程参数 | sites 的导航/任务配置 | 调度动态下发点仍保持其原优先级 |
| `chassis.robot_type`、`sequence_number` 和设备 host | robots/hardware | 型号标识和机器人实例 ID 分开，保留当前实际绑定 |
| `robot_runtime.cpp` 中调度 host/port、协议连接参数 | 部署网络/site/robot 配置 | 与底盘 host 分开；协议消息名和枚举仍在代码 |
| main 与诊断程序中夹爪力矩、滤波、重试等重复设置 | robot_models 的夹爪参数 + 经验证单机覆盖 | 两个入口使用同一来源，单位与默认值一致 |
| `gripper_check`、空抓重试、持件阈值 | defaults 的夹爪/技能策略 + sites/工具覆盖 | 保留“持件候选”和独立抓牢验证的区别 |
| `Robot_Arm_Model.yaml` 的 DH、工具、方向、零偏、采样与限位 | robot_models/kinematics + calibration 的单机校正 | SDK 实际加载的值也要核对，不能只记录磁盘文件 |
| `LowerBody::Params`、腰方向、头/腰/臂物理 ID 与安装相关规格 | robot_models/hardware + 需要时的单机覆盖 | SDK 若有固定约束需显式校验；不能只外置但代码仍写死 |
| `realsense_cameras.yaml` 的 SN/槽位 | robots/cameras | 逻辑 left/right 与实际 SN 分开；缺相机/重复 SN 要明确报告 |
| `cameras` 的流设置、参考点与 `camera_profile_*.yaml` 描述 | 流 profile 归 defaults/vision，SN 归 robots，参考点归 calibration | 统一真实加载来源，移除“描述文件可改但不起效”的歧义 |
| 相机内参 | 设备实测/校准元数据 | 默认按实际采集流读取并记录；没有真实数据不能创建示例内参冒充标定 |
| 顶层头/左手/右手矩阵与 `free_calib/config` | calibration | 核对矩阵方向、mm/m、角度和安装姿态；不能凭旧文件名猜变换方向 |
| 料盘、传送带、单码 YAML | sites 的板几何与感知 profile | 码字典、黑框尺寸、孔距、原点和轴向一致；独立程序的过期流设置不冒充主程序来源 |
| Python `pose_params.yaml` 的模型、类别、算法和几何 | defaults/vision + sites 的工件/检测 profile + 模型清单引用 | 模型类别实际由权重/当前配置核实，旧训练 YAML 单独归档 |
| 模型权重 | `assets/models` + 清单 | 配置引用模型 ID/版本/哈希，不把二进制内容塞进 YAML |
| `devices.json` | robots 的设备绑定 + SDK 认可的启动配置 | 核实 SDK 实际查找位置及 main 前自动配对行为；必须验证实际生效 |
| SDK/Conda 路径、编译平台、库版本 | cmake presets / 环境清单 / 启动环境 | 这是构建/运行环境，不与任务 PD 等业务参数混在一起 |
| 路径、日志等级、图像保存、GUI 与诊断开关 | deployment/runtime 与启动环境 | C++、Python、网页、CLI 同源；诊断不作为默认生产入口 |
| 持件、已放、当前孔、远排记忆与调度进度 | RobotContext/任务会话及状态存储 | 生命周期和失败清理明确，不继续散落成跨文件可写全局 |

数学常量、协议枚举、不可变的数据编码格式不要求全部外置。决定设备/型号/场景/策略差异的内容必须有归属；未被实际读取的历史参数先登记，再在第三步清理。

## 加载与切换

1. 读取明确的 deployment 入口，检查 schema_version、robot/site/model/calibration 的身份和兼容关系。
2. 按约定合并默认 → 型号 → 工位 → 单机允许覆盖项；标定单独绑定，不用任意覆盖掩盖身份错误。
3. 校验类型、必填、未知键、范围、单位、矩阵/坐标系和引用资源；缺关键字段不能静默落到不属于当前机器的默认值。
4. 生成 resolved config、各键来源和配置哈希；与旧版解析结果逐字段对照，确认数值和启用状态一致。
5. 完整成功后发布新快照；动作/任务捕获快照并保持到结束。失败不会改变当前快照。
6. 静态硬件/相机/模型改动需要重启；运动/伺服参数在下一动作或任务边界生效。确有在线业务阈值需求时单独定义一致读取和更新时机，不在控制周期中逐字段改大对象。

未来显式 deployment 参数/环境变量将在第二步实现，现在不应把这些计划当成已可用 CLI。现有 `T170_ROOT`、`T170_CONFIG_DIR`、`T170_LOG_DIR` 在过渡期继续有效，最终也必须与安装布局一致。

## 单机部署应只做什么

选择已验证型号和工位配置，填写真实机器人身份/网络与相机绑定，导入对应工具的真实标定，完成预检和简短现场验收。若另一台同型号机器人需要修改核心源码或复制一份技能实现才能运行，第二步还没有达到目标。

本轮不承诺自动手眼标定或零调参直接上岗；预留标定导入、版本、质量/有效性字段，让以后自动计算结果可以进入同一配置链。
