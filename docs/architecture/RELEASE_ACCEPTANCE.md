## 实机验收门槛

现场对同一个候选提交/制品与对应真实配置记录结果，至少覆盖：

- 料盘抓取与新收手链路：双手、近远排、合爪到上抬的平滑交接。
- 料盘放置：目标孔遮挡时的邻孔/标记定位，左右手、不同孔位、张爪和撤离。
- 两条传送带抓取：窗口 0/1/2 件、一手一件、右手回收与左手伸手交接、空抓重查。
- 现有传送带放置保持原支持范围；当前开环功能不能标成已通过视觉闭环验收。
- 中止、观察丢失、设备/夹爪反馈异常、收手失败等必要错误路径；持件状态与任务上报一致。
- 定义范围内完整上料—转运—下料链路，记录尝试次数、成功/失败、失败原因和节拍；范围、样本数、位置覆盖及连续运行长度由现场共同确认。

验收同时保留原始日志、软件/模型/配置哈希和分析结果。模型内像素/几何误差与编码器 FK 指标不能当成外部测量的物理精度；短时演示不能单独证明长期可靠性。

现有诸如 SDK 限位旁路等试验配置应有明确的发布决策和验证依据，不在目录迁移或打包时静默更改，也不默认视为已验证的物理边界。

## 发布状态与交付物

- 工程任务完成、硬件验证未完成：`v1.0.0-rc.N`，明确列出未满足条目与可测试范围。
- 工程、资源、匹配构建、升级回退和定义范围内实机验收均满足：可定版 `v1.0.0`。
- 发布是团队内部可安装交付，不等于必须公开 SDK、源代码或标定。第三方文件的可分发范围与基础环境依赖要列明。

第一版交付应包含：源码提交/标签、应用包、模型清单/获准提供的资源、独立配置/标定交付、环境清单、安装升级回滚说明、验收报告、已知限制和兼容性。APT 软件源可以之后再建，不作为第一版必须条件。

本轮只建立目标骨架和计划，没有运行机器人、打包发布或自动创建/推送 Git 标签。
