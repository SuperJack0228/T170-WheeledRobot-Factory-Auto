# 倒件检测模型更换

判断和类别编号已经写入当前运行时。传送带门禁见 [`dispatch_flow.md`](dispatch_flow.md) §2.1。

正在使用的权重是 `feeding_cylindrical_parts_alg/models/best1015.pt`，由 `best1020.pt` 覆盖。类别为 0 workpiece、1 feeding_hole、2 fallen。不要动 `bestlatest.pt`。头相机这份权重不要直接用于手相机。覆盖后重启 `t170c_debug` 才加载新权重，不要在这台电脑上启动。

## 类别

| 编号 | 模型 | 用途 |
| --- | --- | --- |
| 0 | workpiece 立件 | 传送带零件、料盘抓取 |
| 1 | feeding_hole 空孔 | 料盘二放置。不计入传送带零件 |
| 2 | fallen 倒件 | 传送带零件。第一次拍照不因此停下 |

`config/move_box_params.yaml` 的 `conveyor` 和 `conveyor2`：`yolo_part_class_ids: [0, 2]`。`kEmptyHoleClassId` 是 1，`kGraspDetectClassId` 仍是 0。`pose_params.yaml` 只有这三类。

## 两次拍照

重叠框 IoU ≥ 0.5 合成一个零件，不按框数相加。同一零件上倒件置信度须比立件高出 0.10 以上才判成倒件；只剩倒件框时也判成倒件。否则用立件。

第一次拍照只看有没有、有几个。立件和倒件都算零件，手臂仍去固定抓取点。

第二次拍照只在夹爪报空、手回到准备位之后。底盘这时还没有出发。

- 窗口内判成倒件：上报 `1102`（和下料点没有料相同），原地等到网页点已解决或未解决。已解决后再拍。右手没抓到、左手还没伸时，按新照片的件数重抓（两个就先右后左）。右手已经夹住、只是左手没抓到时，右手不松开也不动，只让左手再抓。未解决停在原地等下一条。等待期间不发 `PICK_UP_DONE`。
- 立件更高或两者接近：在抓取窗口内再抓一次。再抓仍空就按没抓到继续。
- 窗口内没有零件：没抓到或被碰走，发 `PICK_UP_DONE`，按手里实际有没有件继续。

`yolo_min_conf` 保持 0.25。

## 验证结果

验证集 208 张：倒件召回 0.972，精确率 0.977。传送带 56 个倒件里 1 个被认成立件，料盘 73 个里 3 个。立件被认成倒件的只有料盘上 2 个。
