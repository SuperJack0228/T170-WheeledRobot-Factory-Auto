# 传送带抓取：复用料盘抓取链路

日期：2026-11-02。基于 `f627f32` 修改。范围只包括传送带抓取的流程迁移，没有增加识别模型、抓取规划算法或新的操作命令。

## 计数和时序

保留现有目标区域计数规则：

- 0 个：不抓。
- 1 个：右手抓一个；右臂锁定时使用左手。
- 2 个及以上：两手各抓一个，保持先右后左的现有节拍。右手合爪后开始收回，同时左手开始伸手。

保持原来的抓取窗口、码坐标系抓取点、固定 Z、左右手姿态、准备夹爪开度、空抓后的回准备位及检查/补抓规则。

## 统一后的动作链路

1. 沿用现有头相机计数、传送带码定位和抓取点配置。
2. 按传送带原有接近速度伸到上方，进入料盘同一个闭环下降入口。固定姿态，修正 XY；高度映射、延迟补偿、PD、预测制动和下降协调均复用原控制器。
3. 下降成功后，料盘与传送带调用同一个 `finish_servo_grasp()`：持续保位、按现有抓取条件复核、合爪前启动收手预规划、停止观测、合爪并记录反馈。
4. 正常视觉闭环不再在到位后固定等待 0.5 秒。显式关闭 `hand_descent_correct` 时，保留原开环等待行为。
5. 合爪期间从最终修正后的保位关节角预规划上抬和回程。合爪完成后，由播放线程接管保位，使用料盘相同的起点连接、五次曲线衔接和 SDK 备用加减速轨迹。
6. 收手目标位置与姿态仍按原工位选择；原来的“保持腕角平移，再额外以 40°/s 转腕”改为一条返回原目标姿态的规划轨迹。实际效果需要现场确认。
7. 本轮所需手臂成功收回后，再执行已有的完成回调和离站请求。去掉原来合爪后固定两秒即离站的定时触发，不改变离站目标。

最终抓取高度、抓取容差和夹爪判空规则没有增加新的配置或收紧门限；继续使用现有料盘抓取控制参数。传送带手相机仍使用原来的 class 0 目标及左右抓取 profile。

## 两手交接修正

原 `prepare_group()` 会清理两手的保位状态。传送带右手收回、左手开始伺服时，可能清掉右手还未移交的保位。

现在按本次实际执行的手选择性准备：左手开始时只重置左手，右手的保位一直保留到右手收手线程接管。料盘双手同时执行时，仍按原方式准备两手。

## 空抓与失败

- 空抓仍交给原有计数和重查逻辑。由于空抓的回程目标可能改为准备位，会先丢弃按正常回程目标预规划的缓存，再从保位起点重新规划。
- 收手失败保留错误码及持件状态，不再盲目执行旧的备用抬升/回程组合，也不触发成功离站。
- 右手收手线程的异常会被记录并回收线程；左手异常退出时也会等待右手线程结束，避免线程析构导致进程终止。
- 合爪反馈、是否空抓仍沿用 `gripper_grasp_empty()`，本次没有更改夹爪阈值或新增持件检测。

本次不修改 YAML 数值。继续使用：
