# 料盘二放置偏差：现场与程序状态

记录日期：2026-10-09。本文只描述机器人、计算链、文件中的数值，以及操作者在现场看到的现象。不包含原因判断，也不包含修改建议。

## 1. 工作场景

设备是 T170C 轮式双臂机器人，序列号 `TH-T170C-0124`，型号 `T170C2.0`。工程目录 `/home/ti5robot/T170Clean`。调试进程是 `build_robot/t170c_debug`，监听 `127.0.0.1:8099`。客户端命令为 `python3 tools/debug_client.py <cmd>`。

工厂动作是在料盘和传送带之间抓取、搬运圆柱零件。与本次偏差直接相关的是料盘二的空孔放置。底盘站点在 `config/move_box_params.yaml` 的 `chassis`：

| 名称 | 站点 | 用途 |
| --- | --- | --- |
| 料盘一 | AP7 `tray_station` | 毛坯抓取 |
| 传送带一 | AP5 `belt_station` | 传送带一 |
| 传送带二 | AP6 `out_station` | 传送带二 |
| 料盘二 | AP9 `tray2_station` | 空孔放置 |

底盘主机 `192.168.192.5`。本次精度测试命令 `tray2` / `tray2_place` 不导航，底盘保持原地。`cycle3` 和调度里的真实放置仍会导航到 AP9，不在这次贴纸观察的流程里。

手臂基座系：+X 向前，+Y 向左，+Z 向上。手臂基座随腰移动。头相机装在头部末端，识别料盘时俯视料盘。

## 2. 料盘二

料盘为 6×6 孔，孔径 38 mm，孔心距 75 mm。操作者说明料盘按该孔距定制。四个角上为 ArUco，字典 `DICT_6X6_1000`，无中心码。打印外边 40 mm，程序使用的黑框边长 32 mm，四角码中心距 300 mm。配置在 `board_yf100_aruco/config.yaml` 的 `tray2`。

码的朝向：码的「上」指向照片顶部。照片顶部为远离机器人的一侧，对应料盘 +X、ArUco 第 1 行。照片底部为靠近机器人的一侧。

| 位置 | ID | 在照片中 |
| --- | --- | --- |
| 前左（远、+X +Y） | 0 | 左上 |
| 前右（远、+X −Y） | 1 | 右上 |
| 后左（近、−X +Y） | 2 | 左下 |
| 后右（近、−X −Y） | 3 | 右下 |

料盘系：原点在四角码中心，+X 向前（远），+Y 向左，+Z 向上。孔网格在该平面上，相对原点的 `offset_x_m`、`offset_y_m` 均为 0。行沿 +X，列沿 +Y。列 1–3 分给右手，列 4–6 分给左手。离机器人的远近另按基座 X 排序，`from_robot = 1` 为最远。`far_row_max: 3`，即 `from_robot` 1–3 为远三排。

料盘一使用另一套字典和 ID（`DICT_5X5_1000`，ID 2/5/6/7），与料盘二分开。本次偏差观察对象是料盘二。

头相机调试图 `picture_debug/head/tray_yolo_20261009_155908_478.jpg` 的叠加文字包括：`tray=OK`，`ids=[0, 1, 2, 3]`，`n=4/4`，`reproj=1.27px`，`tilt=0.7deg`，`fuse=3/3`，`holes=6x6 pitch=75mm d=38mm`。图上孔位圈画在金属孔边缘。操作者对照该图说明每个孔在图像上是对准的。

识别：头相机取 3 帧（`tray.fuse_frames: 3`），四角码 `solvePnP`（`SQPNP`，再 `solvePnPRefineLM`）得到料盘在相机系中的位姿，再变到手臂基座系。空孔类别为 YOLO class 3（`feeding_hole`）。放置点的 XY 来自该料盘位姿下的理想孔心，不是来自孔在图像里的单独测距。

## 3. 精度测试时机器人实际做什么

命令 `tray2` 进入 `vision_place_tray2_precision`（`orchestrator/cpp/robot_runtime.cpp`）。顺序：

1. 腰先回 home 高度，再进入放置蹲姿。不移动底盘。
2. 头到标定俯仰。近排使用 `head.pitch_deg: 40`，偏航 0，横滚 0。
3. 双臂到料盘二待机姿态。
4. 开始时左右夹爪张开。每一组伸手之前闭合。伸到孔后张开，停在孔上，直到在运行 `t170c_debug` 的终端按键，然后收回，再去下一组空孔。
5. 已伸过的孔按 ArUco 行列号记住，不再伸。
6. 远三排（`from_robot` 1–3）：腰相对 home 的 X 再向前 `waist.far_row_forward_m: 0.20` m，头俯仰改为 `head.far_pitch_deg: 47`，按当时编码器重算相机外参并重新拍照分配。近三排头俯仰回到 40°。

腰高：home 的层 3 TCP 为 `[0, 0, 0.63, 0, 0, 0]` m。放置蹲姿高度 `waist.ready_z_m: 0.36` m，相对 home 的 X 向前 `ready_forward_m: 0.03` m。

每一组都会重新拍照。外参在检测时由 `load_head_cam2robot` 按头部编码器现算，不使用进程启动时缓存的那一份。

手腕姿态由 `from_robot` 行号选择，单位度，顺序为绕 X、绕 Y、绕 Z。左右手 Z 转角符号相反。配置在 `tray2_place.row_place_rpy_deg` 与 `row1_rpy_deg`。`tray_row_pose_group(row) = 2 - ((row - 1) % 3)`，第 1 行单独使用 `row1_rpy_deg`。

| from_robot 行 | 右手 rx, ry, rz | 左手 rx, ry, rz |
| --- | --- | --- |
| 1 | 0, 40, +30 | 0, 40, −30 |
| 2、5 | 0, 55, +50 | 0, 55, −50 |
| 3、6 | 0, 60, +60 | 0, 60, −60 |
| 4 | 0, 45, +40 | 0, 45, −40 |

下发位置在视觉孔心之上再加 `tray2_place.offset`（手臂基座系，米）。写本文时文件中的值为：

| 手 | x | y | z |
| --- | --- | --- | --- |
| 左 | 0.038 | 0.005 | 0.01 |
| 右 | 0.038 | 0.015 | 0.01 |

操作者描述的 32–38 mm / 7–13 mm 是未加这组孔位偏置时的目测。本文写作时上述偏置已经写在文件里。没有记录说明贴纸观察和这一组数字是否来自同一次运行。

Z 的下发：最终高度是视觉孔位高度加上表中的 z，不是 `head_grasp.hover_above_m`（0.08 m）。0.08 m 只用于接近过程中的上方点。若视觉孔位 Z 与腰高参考相差超过 `tray.z_refine_max_m: 0.003` m，Z 改用参考高度；XY 仍用视觉结果。参考为 `z_ref_m: -0.618`（腰在 `z_ref_waist_z_m: 0.55` 时的盘面）。

到位判定：电机停止后，用编码器正运动学得到的 TCP 与下发点比较。阈值 `bezier_endpoint_xyz_tol_m: 0.008` m，`bezier_endpoint_rpy_tol_deg: 3` 度。料盘二放置的接近速度为 0.16 m/s，轨迹为抹角。

## 4. 从图像到 TCP 的计算

TCP 定义：法兰坐标系 +X 方向 0.260 m，左右手相同。`config/Robot_Arm_Model.yaml` 与 `src/function.cpp` 中 `m.tool << 0.260, 0, 0, 0, 0, 0`。该长度曾为 0.230 m，于 2026-10-09 改为 0.260 m 用于测试。姿态变化时，程序绕这个 TCP 转动，不另加夹爪几何。

左右臂模型不同。右臂肩部 `d = +0.191` m，左臂 `d = -0.191` m。左臂 `model_direct` 在关节 0、3、5 为 −1，关节 1 的 `model_offset` 为 −π/2；右臂对应为 +1 与 +π/2。工具向量相同。

头相机到手臂基座：

```
T_base_cam = T_base_head * T_head_cam
```

`T_base_head` 的旋转为 `Rz(yaw) * Ry(pitch) * Rx(roll)`，平移为 `(0, 0, link_length_mm)`。`link_length_mm: 162`。角度来自头部编码器。`T_head_cam` 读 `free_calib/config/camera_to_head_connector_result.yaml`，注释含义为相机系到头部电机末端系。矩阵平移单位是毫米，乘完后 `T_base_cam` 的平移改为米。

孔在手臂基座系中的位置：

```
p_base = T_base_cam * T_cam_tray * p_hole_tray
```

`p_hole_tray` 为间距 75 mm、关于四角中心对称的网格点。再加第 3 节的基座系 offset 和对应行的 RPY，发给手臂。

头部电机 CAN ID：偏航 30，俯仰 31，横滚 32。2026-10-09 之前机器人侧俯仰与横滚的编号与标定软件不一致；当日改为俯仰 31、横滚 32，与标定软件 `head_ids: [30, 31, 32]`（偏航、俯仰、横滚）一致。标定软件 `headConnectorPoseFromDeg` 的姿态为平移 0，欧拉角取横滚、俯仰、偏航。

头相机：Intel RealSense D435I，序列号 `261722072173`（`config/realsense_cameras.yaml`）。左右手相机为 D405，料盘二放置定位不用手相机。

## 6. 现场看到的偏差

观察方式：执行料盘二逐孔伸手。夹爪到达后再目测，并在料盘上用贴纸标出实际到达位置。多次测试。数值为操作者估算，没有逐孔的尺子记录表，也没有记录偏差的正负号。

操作者对现象的描述：

- 每一个孔都有偏差。X 约 32–38 mm，Y 约 7–13 mm。
- 孔与孔的数值不同，有的接近范围里较小的一端，有的接近较大的一端。多次测试中，偏差出现的方向有规律，不是每次换一个方向。
- 同一下发目标若重复到达，实际落点几乎是同一个点，该点与孔心不重合。
- 终端里编码器读数以及由编码器反算的 TCP，相对下发目标的差非常小。操作者说明：这只表示电机按运动学模型执行到了下发点，不表示夹爪上被目测的那个位置在孔心上。
- 操作者对照调试图说明图像上的孔是对准的，并说明料盘孔距是按 75 mm 定制的。

更早一次口述曾把整体描述为 X 约 35 mm、Y 约 10 mm，并说同一行不同列、不同行之间还有大约 0–5 mm 的差别。随后改述为上面的 32–38 mm 与 7–13 mm。两次口述的对象都是未加孔位偏置时的目测。

另一次相关测试是 `tray2center`：双手先后到视觉给出的料盘坐标系原点，Z 再向上 0.05 m，到位后再等 2 s 读编码器。该命令的夹爪保持闭合，不在这次逐孔贴纸数据里。其中一次记录里，部分到达的编码器反算 TCP 与下发点大约差数毫米；操作者同时看到目测位置与料盘中心仍有厘米级差别。该次测试的最后一次右手到达被操作者要求忽略。没有把这次中心点数据和 36 孔贴纸数据配成同一张表。
