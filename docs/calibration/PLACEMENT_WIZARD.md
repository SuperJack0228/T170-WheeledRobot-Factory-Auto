# 料盘抓取与放置标定向导

本版把原放置向导改为两种独立的料盘标定。每只手保存一份抓取和一份放置标定；不写入传送带偏置，不修改传送带手相机参考。界面版本1.3.0，Web API版本6。

## 启动

仍只启动一个拥有电机、夹爪与相机的 `t170_factory`。标定时不带 `--dispatch`，先退出调度并等待当前动作结束，不并行启动第二个机器人进程。

```bash
cmake -S . -B build_robot -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build_robot --target t170_factory -j4
./deploy/run_factory.sh 2>&1 | tee startup.log
```

保留现场已有的额外SDK/CMake参数。重启原Web服务；如手动启动：

```bash
python3 web_debug/server.py --host 0.0.0.0 --port 8080
```

访问原Web调试台的“标定向导”或 `/calibration`，沿用token。新机器人先标定左右手料盘抓取，再用实际传送带抓取动作取得零件，最后分别标定左右手料盘放置。传送带抓取继续使用它自己的配置。

## 固定目标和姿态

- 按机器人视角：第五行=离机器人最近的第二排；左手选择从左数第二孔，右手选择从左数第五孔。
- 页面显示物理行列，并同时显示实际内部编号。程序按头相机网格在基座中的X/Y排序，不能直接把物理列号当ArUco列号；料盘转向后仍选择同一物理位置。
- 开始前清空第五行。程序需从完整网格确定物理第五行，并确认所选目标为空孔。
- 所有料盘放置行、放置准备位统一使用原第五行的左右手姿态。正式外置参数为 `tray2_place.rpy_deg.left/right`。旧行姿态配置仍可读取，但只取原ready2作为统一姿态，不再为各行建参考表。
- 料盘抓取的各行姿态保留原样；所有行共用该手的一份抓取标定，不按倾角拒绝或回退。
- D点为对应生产C点上方10/15/20mm，默认20mm；只有XY微调，不再下到C精调。C和孔口不是同一个高度概念，程序分别记录生产高度、参考TCP位姿、孔口与零件顶面高度。

## 六个页面

1. **选择任务与准备**：选择料盘抓取/放置及左右手。确认工位、第五行清空和空间。建立会话后再明确点击准备。抓取为空爪，到准备位后按位置闭合到位并保持，不等待“夹到零件”的力矩事件。放置必须事先通过实际传送带流程持件，准备前检查夹爪反馈，保持夹持，不张爪、不人工喂件。
2. **识别固定空孔、去D**：点击头相机识别，核对自动选择的固定孔，再点击接近。无历史XY偏置，Z使用对应任务的生产设置（包括仍启用的Z项）。先到观察位，再停在D。
3. **D点XY对准**：提供0.2/1/2/5mm单步按钮，固定姿态和Z。每次动作结束才接受下一次，合位移上限5mm。确认保持当前XY竖直下降的工作中心对准目标孔，记录反馈XY与无偏置目标的差。不要只用斜视图中两指中点的重合判断真实下降轴线。
4. **保持手臂、准备参考物**：原地张爪。抓取：将一个零件居中放进刚才的孔，推荐居中套，避免宽松孔中的偏心进入参考。放置：人工取走零件，露出刚才的孔。明确确认场景就绪，再拍固定图；不移动手臂。
5. **点击视觉参考点**：抓取点击零件顶面圆心，直接记录人工点，不运行橙色孔环算法。放置点击孔心附近，复用去畸变、平面校正与橙色孔环精定位。带局部放大和十字显示。拍照时同步记录实际TCP位姿和图像版本；换图后旧点击失效。
6. **保存与完成**：确认补偿和参考点后保存、加载并备份旧文件。不强制重新装件或伺服回放；状态明确为“已完成人工标定，尚未验证实际作业精度”。可明确点击“抬离并返回准备位”，也可直接结束会话；结束本身不移动、不松爪。

## 外置数据与生产接入

文件位于 `$T170_CONFIG_DIR/calibration/`；未配置覆盖时使用工程 `config/calibration/`：

```text
grasp/left.yaml
grasp/right.yaml
placement/left.yaml
placement/right.yaml
```

- schema 2，带 `task`、`scope: tray_only`、`validation_kind: manual_at_D`、`field_verified: false`。`validated: true` 表示人工步骤和数据校验完成、可加载，不表示通过了实机精度验证。
- 保存任务引导XY补偿、参考像素、参考TCP完整位姿、特征平面高度、相机内参和畸变、机器人编号、相机序列号、手眼及工具模型指纹和会话日志位置。
- `reference_tcp_above_plane_m` 中的plane是该参考特征平面：抓取为零件顶面，放置为料盘孔口。运行时结合当前高度进行原有几何换算，避免把两种平面混用。抓取顶面使用固定工位参考加 `tray.part_above_tray_m`，不取手相机深度。
- 生产料盘目标使用对应任务/手的标定XY，替代旧整盘XY和逐行XY；Z不在本次标定中重算。
- 抓取参考只在料盘抓取显式标记的会话中注入配置副本。普通/传送带class-0会话不读取料盘抓取标定；标记一次消费，动作作用域退出时清除，原全局参考保持原值。
- 放置使用同一手的单份参考，所有行采用统一姿态。抓取按要求保留不同姿态，并沿用现有高度映射，不新增跨姿态自动辨识算法；远近行效果仍需实际验证。
- 同手/任务新文件优先于旧 `*_tilt_*.yaml`，旧文件不删除；在没有新文件时，旧放置文件仍按原倾角匹配读取。`*_before_*.yaml` 是备份，不参与加载。
- 保存与加载不自动打开 `visual_servo.tray_place.enabled` 等生产开关。当前现场配置放置伺服仍关闭；要验证放置手相机闭环，应明确在生产配置启用该开关，且 `cameras.hand_descent_correct=true`。
- 相机、工具模型、夹持方式或统一放置姿态改变后需重新标定。一次人工标定不能自动消除全部位姿相关的运动学/手眼误差。

## 记录、停止和验证

日志在 `debug_picture/calibration/<session>/`：输入配置快照、`session.json`、带请求/结果/实际位姿的 `events.jsonl`、固定图像及参数、`draft.yaml` 与保存记录 `validated.yaml`。后者同样用 `field_verified: false` 表示实机验证仍未完成。

取件/放件前后会检查手臂位姿是否保持；拍照还会检查机械臂是否稳定。编码器不变不能排除受力回弹，保存后仍应做实际作业验证。D点上抬20mm也不构成所有工件尺寸下的防碰保证。

停止可在动作期间请求，停止后本会话不再允许继续运动；可退出并检查现场，再解除软件停止。退出不回位、不松爪、不失能。标定期间普通动作、调度启动、配置重载和Web配置写入均被阻止。网页刷新恢复当前会话，不自动重放动作。

首次验证建议：先单手固定孔走完抓取标定，再验证料盘抓取；实际传送带持件后完成放置标定，再验证固定孔、其他行。记录实际偏心和对应日志，不能把离线测试或向导保存成功当作抓放精度已达标。
