# 料盘放置标定向导

本版本新增 Web 独立向导与机器人端标定会话。已做离线验证，尚未在 T170 上验证运动、取件回弹和标定精度。

## 启动与入口

仍由一个 `t170_factory` 进程拥有硬件；网页不直接控制 CAN，也不另启一套电机驱动。机器人先到料盘二工位，标定过程不导航底盘。

机器人上重新编译（保留现场额外的 SDK/CMake 参数）：

```bash
cmake -S . -B build_robot -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build_robot --target t170_factory -j4
./deploy/run_factory.sh 2>&1 | tee startup.log
```

标定时不带 `--dispatch`。如果已经进入调度，先按现有方式停止并退出，等待动作结束。不要并行启动第二个机器人进程。

重启现有 Web 服务；若手动启动，仍使用：

```bash
python3 web_debug/server.py --host 0.0.0.0 --port 8080
```

访问原 Web 调试台，点击“标定向导”，或访问同一地址的 `/calibration`。沿用 Web 服务 token 登录，网页刷新能恢复仍在运行的标定会话。页面/API版本更新至 1.2.0 / 5，必要时强制刷新。

## 八个页面

1. **选择与准备**：选左/右手、生产姿态组、近/远三排、D 相对生产 C 的距离（默认20mm，可选10/15mm）。建立会话后，单独点击准备。仅选定手臂去准备位，头/腰走对应观察姿态，夹爪张开；此时不要装件。
2. **装入零件**：按生产夹持方式人工装件。复用 `graspAndWait` 的反馈力矩闭合；空合或超时不能进入下一步。超时调用位置保持，结束持续闭合目标。
3. **识别目标、去D**：只列当前姿态/近远区对应的空孔，人工选择行列。先到上方观察位，再到 `D.z=C.z+clearance`。不叠加历史经验XY偏置，Z仍使用工位/生产高度；不是头相机深度。
4. **初始引导补偿**：用基座XY的0.2/1/2mm按钮微调，每次单次移动并停稳，自动刷新手相机固定画面，也可单独点击刷新。记录反馈位姿差，得到D点初始补偿。
5. **C点精确对准**：下到同一生产C，固定TCP姿态微调XY。确认实物居中后记录最终补偿；它替代初始补偿，不重复叠加。此处补偿是“任务引导补偿”，不是重新求解头相机六维手眼。
6. **记录孔心参考**：保持手臂，明确点击张爪，人工取走零件，再拍固定图像。程序检查松爪取件前后的反馈位姿差。点击选择真正目标孔，程序在去畸变/平面校正图中拟合橙色孔环，再返回原图坐标。图像重拍后旧点击失效。
7. **持件回放验证**：先抬离返回准备，再人工装件合爪。重新识别相同目标孔，用草案补偿与参考运行已有单手伺服。下降结束仍不自动张爪；点击张爪后确认实物结果，再抬离返回。只有伺服完成和人工实物确认均通过，才允许保存。
8. **保存完成**：以独立文件保存、校验并加载，显示文件与日志位置。结束会话后才能恢复普通动作。不要把“状态机执行成功”当作精度已经达标。

页面只改变显示，不因翻页自动运动。回看旧步骤不能执行旧动作。每条请求带会话与唯一编号，重复请求返回原结果；并发动作直接拒绝，不排队后突然执行。

## 数据和生产接入

- 正式数据：`$T170_CONFIG_DIR/calibration/placement/<left|right>_tilt_<roll>_<pitch>.yaml`。未配置目录覆盖时在工程 `config/calibration/placement/`。
- 同一工具俯仰/横滚族共享参考，不按料盘每一行建立补偿表。文件名按5°取整便于管理，实际匹配使用记录倾角的2°窗口；yaw由几何映射处理。近/远排的55°可复用，45°需分别验证标定。
- 保存同一倾角族会备份旧文件，`*_before_*.yaml` 不参与加载；其他倾角族不会被覆盖。
- 正常料盘放置在组装头相机目标时选择匹配倾角的任务补偿，替代历史全盘和逐行XY偏置；Z参数仍沿用生产配置。运行手相机时选择同一倾角族的参考。
- 尚未标定的倾角保留 `move_box_params.yaml` 中显式配置的原有行为，日志给出提示，不把其他倾角的标定错误套用。它不代表该倾角已经完成精度验证。
- 校验机器人编号、相机序列号、分辨率、手眼与工具模型文件指纹。不同硬件/模型不能默默复用；指纹是可追溯摘要，不是加密签名。
- 保存参考像素与参考时TCP距盘面的高度；运行时自动换算相对C的内部高度。因此改变C不会仅因参数含义混淆而改变视觉瞄准线。旧的 `reference_height_m` 配置仍兼容。
- 抓取参考与底层手眼矩阵不被标定保存动作改写。

日志在 `debug_picture/calibration/<session>/`：

- `inputs/`：开始标定时的参数、相机、工具模型与手眼文件；
- `session.json`：最近步骤状态；`events.jsonl`：动作、参数、结果、位姿及失败原因；
- `frame_<n>.jpg/.json`：固定图像、内参/畸变、采图时间与前后位姿；
- `draft.yaml`、`validated.yaml`：未验证草案与验证后结果；
- 回放的详细PD/几何/运动日志仍在原 `logs/visual_servo/`。

同时修正生产调试图参考十字的平面口径，使其与控制器按同一孔口平面换算。

## 停止与退出

停止指令不等待普通动作锁。停止后本会话禁止继续运动，允许退出；退出后可在首页明确确认现场，再解除软件停止（不复位硬件急停），无需先运行其他动作；退出本身不松爪、不回位、不失能。短步微调没有持续速度命令，网页断开不会导致一直点动。

普通动作、调度启动、配置重载在标定会话期间由机器人端阻止。网页配置写入也会拒绝。刷新页面可恢复当前会话；机器人进程重启后不自动恢复物理步骤，旧日志仅供查阅。

如果机械臂中途失败，界面保留明确错误，不能跳过后续验证保存。先停止并退出，检查实际状态后重新进入准备流程。取件前后即使编码器一致，也不能排除负载回弹，因此必须持件回放。

## 首次实机验证建议

先单手、近排、ready1，完整走一次向导。重点记录：准备/微调是否平滑、D和C高度、取件前后位姿变化、孔环精定位是否选中真正目标孔、回放实际偏心。再做另一只手及其他倾角族。D上抬20mm并不构成所有工件/夹持深度下的防碰保证。

本版没有加入自动像素到毫米辨识、自动接触找正或力控插入；保持既有几何映射与PD。用鼠标选孔不等于重新标定完整相机/机器人几何。

## 离线检查

```bash
cmake -S . -B build_offline -DT170_SERVO_TESTS_ONLY=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build_offline -j4
ctest --test-dir build_offline --output-on-failure
```

需要 OpenCV、yaml-cpp、jsoncpp、Python；HTTP测试只监听本机随机端口并使用假机器人，不初始化硬件。
