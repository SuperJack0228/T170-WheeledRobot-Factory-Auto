# T170 双臂运动学 SDK 评估与升级需求

日期：2026-11-06。评估对象：`Robot_Arm`、`Ti5_Arm_2204.so` 及上层运动适配。当前本地 Git 基线：`6c5256e`。

## 1. 反馈结论

当前优先补齐的能力是：**以指定关节状态连续跟踪笛卡尔路径，并在真实约束内管理七轴冗余构型**。单点位姿可解、末端路径连续、关节路径连续和驱动实际跟上是不同的验收条件，不能以其中一项替代其余几项。

建议将升级分为连续路径与诊断、构型偏好与约束优化、双臂及腰臂协调三批交付。第一批不需要强化学习，也不要求立即重写整机全身控制。保留现有 FK 和可用解析 IK，在接口、连续选解、可配置次任务和约束处理方面升级即可形成实质改善。

本文基于 SDK 公开接口、现场日志、现有离线复算记录及源码编制。闭源算法行为以接口和可复现实验为依据，现场记录与复算结果分别列示。

## 2. 输入材料及需要修正的归因

输入包括 `ARM_KINEMATICS_ASSESSMENT.md`、2026-09-30 的 `ARM_IK_ELBOW_WRIST.md`、当前 SDK 头文件、模型 YAML、连接器、局部求解器、V3 撤离实现，以及五组 11 月 4 日现场 CSV。

### 2.1 历史与当前版本

9 月材料中的 J2 搜索、J6 限位及 TCP 参数不能直接作为当前配置。当前 YAML 工具长度为 0.260 m，9 月材料引用 0.230 m；当前左右 J6 模型限位为 ±40°，不能沿用历史“已改为 ±90°”的结论。

当前 V3 已采用连续局部 IK 上抬、固定示教电机关节位返回和共用时间规划／反馈执行，临时放宽 J2、准备位在线 IK 等历史办法已移除。故障用例仍有 SDK 回归价值，但不能写成现行撤离链路始终采用旧连接器或完全没有反馈。

### 2.2 SDK 已有能力与缺失合同

SDK 已公开 FK、Jacobian、混合 IK、指定冗余关节的解析 IK、数值 IK、笛卡尔直线和关节轨迹。数值 IK 的头文件明确写有阻尼最小二乘及零空间；因此不应反馈“SDK 完全没有零空间算法”。

当前公开接口没有清楚暴露独立的偏好构型、肘部几何目标、次任务权重、任务优先级及逐次求解诊断。`Inverse_Kinematics_Numeric` 的参数注释甚至只标记关节向量为输出，种子是否输入、是否被正确保留，需要维护者明确。

### 2.3 限位不能跨角度空间直接比较

SDK 对外使用电机角 rad，限位 YAML 使用模型角 deg，`Check_Joint_Limit` 内部先转换。历史材料中“电机 J2≈45° 大于模型 J2 上限 5°，所以必然非法”的推理不成立。

必须由 SDK 输出每关节电机角、转换后模型角及实际加载限位。若转换约定为 `q_motor = direct·q_model + offset`，则右 J2 的 +90° 偏置会使电机 45° 对应模型 -45°；这一例子说明直接比较数值会误判，具体公式仍需维护者确认。

同样，机械臂曾经停到某个位置不等于该位置满足全部物理安全条件；原始电机行程、线束约束、自碰撞和应用偏好需要分开建模。

## 4. 公开方案的可借鉴机制

公开代码反映的是对应实现的技术机制，不代表任何公司的全部量产运动栈。以下按适用层级比较，不以展示视频或最新论文替代部署成熟度证据。

### 4.1 宇树 G1 双臂：优化目标中同时表达末端、连续性和构型偏好

宇树官方 `xr_teleoperate` 的 `G1_29_ArmIK` 使用 Pinocchio 与 CasADi，目标中包含末端位置、旋转、关节正则及相邻求解差，另施加模型关节范围约束。值得借鉴的是显式表达“解到哪里、靠近哪种构型、与上一次差多少”。这份公开遥操作实现采用加权目标，不能据此认定其提供严格路径保持或完整自碰撞保证。其关节零位正则也不能原样等同于 T170 的拟人姿态。

来源：[官方求解器源码](https://github.com/unitreerobotics/xr_teleoperate/blob/main/teleop/robot_control/robot_arm_ik.py)。

### 4.2 Pink：可配置任务式微分 IK

Pink 基于 Pinocchio 及 QP 求解。`PostureTask` 的目标可以显式设定，也可从当前构型初始化；并非只能追随当前构型。这适合分开表达末端位姿、期望关节姿态和阻尼任务。普通加权任务不自动具有严格主次优先级；孔边姿态误差上限需要另外明确约束或分层求解。

来源：[项目](https://github.com/pink-kinematics/pink)、[PostureTask 源码](https://github.com/pink-kinematics/pink/blob/main/pink/tasks/posture_task.py)。

### 4.3 Mink 的 G1、Apollo：统一模型中的多任务与碰撞约束

Mink 提供基于 MuJoCo 的微分 IK 及配置、速度、指定几何对的碰撞限制。G1 桌面示例同时包含双手、躯干、骨盆、足部、质心和姿态任务，并配置部分手—桌面／大腿碰撞对；Apollo 示例显示躯干可参与头部目标跟踪。它们是开源模型示例，不是 Apptronik 或宇树量产控制器披露，也不意味着配置一次示例就覆盖全部碰撞。

来源：[Mink](https://github.com/kevinzakka/mink)、[G1 源码](https://github.com/kevinzakka/mink/blob/main/examples/humanoid_g1.py)、[Apollo 源码](https://github.com/kevinzakka/mink/blob/main/examples/humanoid_apollo.py)。

T170 可先使用固定基座的腰＋双臂统一模型，不需要为轮式平台照搬双足平衡任务。

### 4.4 SEW 臂型角：用几何描述冗余

SEW（Shoulder–Elbow–Wrist）角描述肘部围绕肩—腕连线的方位，提供比单个电机角更直观的构型参数。Elias 与 Wen 的广义／立体投影 SEW 工作给出相关参数化、奇异性分析及多种七轴结构的 IK 实现。参数化本身仍有退化位置，不能称为全工作空间无奇异。

来源：[论文](https://arxiv.org/abs/2307.13122)、[stereo-sew 实现](https://github.com/rpiRobotics/stereo-sew)。T170 需核对肩、肘、腕中心及关节结构后适配，不能直接套另一机型公式。

#### 4.4.1 臂型角的几何含义

在理想肩—肘—腕结构中，给定肩中心 S、腕中心 W 和上／前臂长度后，肘中心 E 的候选位置构成绕肩—腕轴的圆。臂型角 ψ 表示肘在这个圆上的方位。肘弯曲程度与臂型角是不同概念：前者反映上臂与前臂夹角，后者反映手肘围绕肩—腕轴的摆放方向。

对实际七轴机构，可先由各连杆 FK 定义肩、肘、腕几何点，再评价 SEW 角；这些几何点是否对应理想 SRS 结构，以及指定 ψ 后能否解析求解，需要结合 T170 的实际轴线确认。给定 TCP 位姿时，应先按工具变换得到腕中心，不能将 TCP 抓取点直接当作 W。

#### 4.4.2 一种可用于接口讨论的有向角定义

所有点和方向在同一躯干／肩基座坐标系表达。令 a 为肩—腕轴，r 为肘偏移在该轴正交平面内的分量，选择一个有物理意义的参考方向 b，并投影得到基向量 u、v：

```text
a = (W-S) / ||W-S||
r = (E-S) - a · [aᵀ(E-S)]
u = [b - a(aᵀb)] / ||b - a(aᵀb)||
v = a × u
ψ = atan2(vᵀr, uᵀr)
```

这是明确参考方向后的几何定义示意，不是将某个公式未经适配直接部署。b、左右侧符号、零角参考、肩肘腕点及角度单位应写进模型合同；左右臂采用一致几何语义，不直接对电机角取负号。

当肩腕重合、肘偏移 r 接近零，或 b 几乎平行于 a 时，上述表达退化。普通 SEW 的参考奇异、手臂伸直造成的几何退化和机械臂 Jacobian 奇异需要分别诊断。立体投影 SEW 可以改善参考奇异的位置分布，但不能消除全部机构奇异与工作空间边界。

#### 4.4.3 为什么臂型角不能用 J2 代替

J2 是机构中的一个关节变量，ψ 是多个关节共同决定的几何量。固定 J2 后，肩腕轴随末端位置变化，肘方位仍可能改变；保持 ψ 时，为沿直线维持末端位姿，J2 及其他关节反而可能需要协同变化。

即使给定完整末端位姿和 ψ，也可能存在多组离散 IK 解。因此臂型角管理必须同时保留上一帧关节种子、候选分支信息和关节连续性检查，不能仅增加一个 ψ 参数就宣称消除了换支。

#### 4.4.4 T170 推荐使用方式

孔边下降和竖直抬离时，读取当前 ψ 作为局部参考，并以保持当前构型为主；不在工件尚未脱离时强行切换到另一套“标准肘”。自由空间中，使用与任务和目标位姿相关的推荐 ψ 或允许区间，逐步回归正常构型。接近伸直或剩余可行域变窄时，降低肘偏好强度，让末端任务和真实约束优先。

臂型角偏好可使用周期代价 `c_sew = 1-cos(ψ-ψ_preferred)`，避免 +179° 与 -179° 被误判为相差 358°。连续日志可在表示层展开角度；真实关节仍按各自物理行程约束，不能任意跨越关节限位。还需限制 ψ 变化率，防止参考区间切换引起肘部快速摆动。

不建议全工作空间使用同一个 ψ 硬值。针对身前抓取、侧向转运、孔边抬升建立少量姿态 profile；优先配置期望区间和软权重，再在可行域内优化。

#### 4.4.5 SDK 最小接口与诊断交付

- `evaluate_sew(q)`：返回 ψ、肩／肘／腕点、参考定义和有效性；退化时返回明确状态。
- `solve_ik(..., q_seed, sew_preference)`：将求解种子与 ψ 偏好分离，支持期望角／区间、权重及保持当前模式。
- `plan_cartesian_path(..., redundancy_policy)`：按路径保持构型连续，记录实际 ψ、可行余量和候选选择；不能只在终点选 ψ。
- `sew_jacobian(q)` 或等价导数：供微分 IK／QP 使用，明确导数坐标与角度连续区间。
- 运行报告至少包含 `sew_valid`、`sew_actual`、`sew_preferred`、偏好误差、相邻角变化及相关约束；没有有效模型时，不伪造“推荐正常角度”。

首批应先实现和核对 ψ 的计算、可视化及日志，再接入软偏好优化。通过相同 TCP 下改变合法冗余构型、固定姿态短直线、近伸直及左右镜像用例检查其几何语义，最后冻结作业姿态规范。

### 4.5 近期拟人冗余研究：肘引导应随可用冗余空间调整

2026 年 10 月预印本 Human-Like Redundancy Resolution for Real-Time Bimanual Humanoid Teleoperation 将腕部跟踪优先、肘部引导投影到零空间，并在手臂接近伸直时逐步释放肘引导。可借鉴的是“构型偏好不能阻塞主要任务”，而非将其遥操作实验结果视为 T170 的性能保证。

来源：[论文](https://arxiv.org/abs/2610.16855)。

### 4.6 路径规划与时间规划必须分层

Ruckig 适合带速度、加速度和 jerk 边界的状态到状态运动生成；对给定复杂笛卡尔几何路径，不应逐关节独立平滑后假定路径仍保持。TOPP-RA 面向给定路径的时间参数化，常用速度／加速度约束不应直接解释成统一 jerk 保证。cuMotion 提供更高层的碰撞感知 IK、规划和优化，可作为后续避障参考，不是修复局部起点不一致的必要前提。

来源：[Ruckig](https://github.com/pantor/ruckig)、[TOPP-RA](https://github.com/hungpham2511/toppra)、[NVIDIA cuMotion](https://github.com/nvidia-isaac/cumotion)。

## 5. 重点一：固定 TCP 姿态的直线为何被拒绝

七轴、非奇异且末端六维任务独立时，一般剩余一个冗余自由度。直线空间位置 `p(s)` 和固定旋转 `R0` 并没有唯一确定关节路径 `q(s)`。

当前连接器先检查 SDK 轨迹起点与保位参考的最大关节差，超过 0.05 rad 直接拒绝；再搜索受关节速度、加速度、jerk、持续时间及末端几何条件限制的五次连接。固定姿态只能约束末端，不能保证 SDK 重解后的关节仍等于原来的关节。

需要区分四种情形：

1. 起点关节被重解：末端相同，但冗余构型或解析支不同。降速度通常不能消除这个差值。
2. 起点关节相同，但起始速度／加速度与保位或上一段不兼容。需重新定时或显式处理边界导数。
3. 当前参考、实际反馈、SDK 模型或工具变换不一致。应先处理状态和坐标合同。
4. 直线及固定姿态在真实约束下确实不能连续实现。应报告不可行区间，而非强行生成跳变轨迹。

终点可达不保证整条直线存在连续合法解；每个采样点各自可解也不保证这些解属于可连接的同一路径。反向路径可能存在，但正向贪心选解会走入死路。

### 5.1 SDK 的连续路径合同

建议新增显式路径接口，至少接收起点关节、起点速度／加速度、TCP 帧、完整目标位姿、路径约束、构型策略和模型版本。

- 首个输出必须等于调用方指定的起点参考；若实测与参考差过大，返回状态不一致，不能偷偷改起点。
- 相邻路点使用上一解初始化；解析解保留多个候选，按连续性、限位余量和构型代价选择，必要时前瞻而非逐点贪心。
- 固定姿态路径应在每个采样点验证位置、旋转和关节连续性；角度差按实际关节拓扑处理，有限位关节不能任意做 ±2π 包裹。
- 各点动态约束不能靠改写第一行掩盖；离线轨迹要匹配起止导数，在线轨迹要维护上一次命令状态。
- 失败返回路径进度、对应关节、残差、约束及可选可行前缀。执行器是否使用前缀需由任务明确授权。

连接器可保留用于合法小误差交接，但不应长期负责修复 SDK 从另一构型起步的问题。升级目标是减少其承担的职责，而不是取消所有轨迹衔接与反馈检查。

## 6. 重点二：从锁 J2 升级为显式冗余管理

锁 J2 是一种有效的局部冗余参数化，但对所选结构和区域才有合适条件。它不等同于固定几何肘方向，也不唯一锁定其余关节解。某些位姿必须适当改变 J2 才能保持末端姿态，完全锁死会人为删掉本可执行的路径。

建议支持以下策略，而不是所有动作共用一个 J2 开关：

| 策略 | 行为 | T170 用途 |
| --- | --- | --- |
| `hold_configuration` | 末端任务优先，在可行域内贴近进入该段时的构型 | 抓取下降、孔边竖直抬离 |
| `preferred_posture` | 向配置的正常构型缓慢回归，同时受主要任务及约束限制 | 自由空间接近、工位间调整 |
| `preferred_sew` | 允许在指定几何肘方向／臂型角区间内自适应调整 | 常规工作空间中的稳定外展肘 |
| `fixed_joint` | 显式固定某关节，仅在允许区域内使用 | 特定工位、对照试验 |
| `joint_target` | 完成示教关节构型的点到点运动 | 已离孔的准备位／中转位 |

连续求解和正常构型是两项不同目标：只追随上一解，可能连续地保持一个不合适的肘；只追随固定正常构型，可能在孔边引起过大冗余运动。需要按作业阶段切换策略并平滑权重。

## 7. 重点三：将“肘好看”改写为可验收的姿态规范

### 7.1 代价函数，而非必须使用强化学习奖励

建议将拟人偏好写成普通优化代价。定义：

```text
C(q) = w_cont · ||D(q - q_previous)||²
     + w_post · ||D(q - q_nominal)||²
     + w_elbow · c_elbow(q)
     + w_margin · c_joint_margin(q)
     + w_singular · c_singularity(q)
```

其中 D 用关节有效行程等尺度归一化。`q_previous` 维持连续，`q_nominal` 定义任务偏好，二者不能混为一个参数。避碰和物理限位还需硬约束，不能仅靠代价惩罚。

### 7.2 肘部几何偏好

由肩 S、肘 E、腕 W 建立肩—腕轴及肘在垂直于该轴平面内的偏移，约束其方向／SEW 区间。可配置：

- 肘与躯干、另一只手臂及工位边界保持距离。
- 身前作业优先适度外展、避免肘内收穿入躯干空间；不要求永远最大外展。
- 腕关节留有活动余量，避免通过手腕接近极限来勉强维持“漂亮肘”。
- 对称目标下左右构型符合各自几何镜像；模型轴方向不同，不能简单把电机角取相反数。
- 限制冗余姿态随路径的变化率，减少肘摆动。

不能把肘的三个位置分量全部设为独立硬目标：固定六维末端之后通常只剩一维自由度，任意肘位置未必可达。宜使用软方向目标、区间或明确的几何参数化。

手臂接近伸直、肩腕距离接近退化或 SEW 参考退化时，应降低相关几何偏好的权重或切换表达。保持阻尼并降低进度速度；不能为了保住肘方向牺牲工件旁的末端约束。

### 7.3 最小可交付的姿态规范

第一版由 SDK／机械负责人共同给出：每侧肩肘腕帧、真实关节范围、允许肘侧向区间、推荐构型及工作区、腕部余量，以及三个动作配置：孔边保持、身前工作、自由空间返回。使用少量示教构型建立分区偏好，不需要为每个料盘孔配置姿态补丁。

后续可由示教数据拟合连续 `q_nominal(T)` 或 `ψ_nominal(T)`，并保留确定性约束层。学习偏好是可选增强，不能替代基础运动学与路径合同。

## 8. 推荐的求解框架

### 8.1 单臂连续微分 IK

建议以每周期关节速度或增量为变量，构造带约束 QP。主要任务为末端平移与旋转跟踪，次任务包括构型、肘引导和阻尼。硬约束覆盖真实位置／速度／加速度、指定碰撞距离及路径误差包络。

简化形式：

```text
min_v  ||J_tcp v - ξ_required||²_W + posture/elbow/damping costs
s.t.   q_min + margin ≤ q + Δt·v ≤ q_max - margin
       v_min ≤ v ≤ v_max
       a_min·Δt ≤ v-v_previous ≤ a_max·Δt
       linearized collision-distance constraints
```

孔边阶段应采用任务等式、受控松弛或分层 QP，使末端路径优先级明确；单纯把末端权重设大，不等于严格优先。局部 QP 的碰撞距离线性化也不能代替整段离散／连续几何检查。

速度不够时，降低路径进度 `s_dot` 或协调视觉下降；约束不可行则减速保持并返回原因。不能将任何可行关节动作自动解释为可行的孔边直线。

### 8.2 解析与数值方法并存

保留解析 IK 用于候选生成、快速可达性分析及较大姿态变化，连续数值／QP 方法用于局部跟踪。对七轴冗余角候选可使用前瞻图搜索选择整段一致路径，避免每点最近解走入限位死路。没有必要因补齐约束优化而全面弃用解析算法。

### 8.3 雅可比及模型接口

当前局部解每次迭代对七关节有限差分，SDK 虽有 `Jacobian`，但公开头文件未说明它的表达帧、线／角速度行序、参考点及电机坐标变换规则。应先补齐并用有限差分验证，再用于实时求解。

建议统一提供：FK、各连杆帧、肩／肘／腕位置、TCP 雅可比、肘雅可比、模型—电机角变换、限位及几何版本。Pinocchio 可作为模型与导数参考，不是现有 MDH FK 必然错误的证据。

### 8.4 双臂及腰臂升级

下一阶段建立腰＋双臂＋工具的共同运动学树和基础碰撞几何。先让双臂读取一致腰状态并检查手臂—躯干、臂—臂、工具—台面距离；再将腰作为可选择自由度参与可达性和构型优化。

在孔边抬升期间，腰部动作必须与保持工件脱离的任务共同表达。自由空间返回可启用更大腰臂协同。轮式底盘可先保持固定，不必立刻引入整车导航优化或双足动力学控制。

## 10. 建议接口合同

建议接口包含以下请求与诊断结构：

```cpp
struct IkRequest {
    Pose target;
    JointState seed;            // q, dq, ddq and timestamp
    Vector q_preferred;         // separate from seed
    RedundancyPolicy policy;
    TaskTolerance tolerance;
    ConstraintSet constraints;
    ModelIdentity model;
};

struct SolveReport {
    Status status;
    int failed_sample;
    double path_progress;
    double position_error, rotation_error;
    double sigma_min, constraint_margin;
    int offending_joint;
    Vector motor_angles, model_angles;
    Vector joint_step;
    double solve_time_ms;
};
```

姿态建议内部使用旋转矩阵／四元数及 SO(3) 误差，RPY 仅保留兼容输入并明确旋转顺序。接口另外明确雅可比帧、线角速度顺序、TCP 点、样本周期、线程安全与失败后的输出有效性。不能把所有错误都折成一个 `-3` 或上层 `-16`。

## 11. 最小回归与验收方法

回归与验收覆盖以下六类场景：

1. **原故障重放**：固定原 SDK 库、每次会话模型和工具、参考／实测起点。重放 80 mm 固定姿态抬升及历史返回起点不一致用例，报告路径起点、最大位姿残差、最大相邻关节差和失败进度。
2. **方向与构型覆盖**：两手在常用准备位及近／远排抓放姿态执行 X/Y/Z 正反方向短直线；覆盖多套合法起始构型。可行集由基准求解和实际模型核实，不以“所有目标均成功”为验收要求。
3. **不同速度一致性**：同一几何路径用不同速度参数化，不因调速度改变起点构型；无法满足动态边界时明确降低节拍或报动态约束。
4. **冗余压力测试**：接近限位和伸直区域；比较固定 J2、保持构型和软肘偏好。评价成功率、路径误差、肘方向变化、关节余量及实际耗时，而非只比较最终点。
5. **接口一致性**：FK→IK 回环、Jacobian 有限差分、Model↔Motor 往返、左右几何镜像；不同 IK／轨迹接口对同一候选的限位判定一致。
6. **执行与连续闭环**：从视觉下降最终 q/v/a 交接到抬升，再到示教返回；分别记录命令、反馈和完成时刻。反馈落后、卡住、失联均有确定结果，不将命令末点发送视为到位。

数值指标应结合实际工件净空与驱动能力冻结。可首先约定静止起点命令一致至数值精度，直线误差／姿态误差由工艺给出明确上限；关节 v/a/j 不超过认可限制。SDK 求解记录 P50、P95、P99 和最坏耗时，与目标 5／10 ms 预算对照，不能只报平均频率。仿真模型通过不替代实机 FK、路径和碰撞裕量验证。

## 12. 可直接用于同事沟通的需求摘要

目前部署最受影响的是固定 TCP 姿态直线的关节连续性、七轴冗余构型管理及肘姿态可控性。请优先保证笛卡尔路径以传入关节状态作为真实起点，沿路径连续选解；将求解种子与偏好构型分开，开放姿态／肘方向次任务，不再只用锁 J2 和收窄限位表达动作偏好。请同步提供电机角与模型角转换、真实限位来源、逐关节超限及奇异性诊断，统一单点 IK 与轨迹接口的判定。

升级应允许不可行路径明确失败，但要能解释失败的样本、约束和余量。孔边阶段优先末端直线及姿态，自由空间阶段允许回归示教构型；时间规划与执行反馈另行闭合。首版先解决单臂连续运动及诊断，再扩展双臂自碰撞和腰臂统一约束。
